# Контейнеры STL: выбор структуры и итераторы

- **Трек:** Основы программирования и C++
- **Модуль:** Объектная модель и стандартная библиотека
- **Тип:** урок
- **ID:** `T1-M4-L6`

## Цель и критерий перехода

Выбирать контейнер по операциям и контрактам, а не по привычке.

## Теория

`std::vector` — базовый выбор для последовательности: элементы хранятся непрерывно, быстрый доступ по индексу, эффективный проход. Вставка в середину может сдвигать элементы, а расширение capacity инвалидирует указатели, ссылки и итераторы на элементы. `std::array` имеет фиксированный размер, `std::deque` поддерживает эффективные операции с обоих концов, `std::list` — стабильные итераторы и вставку при известной позиции, но хуже локальность памяти.

`std::stack`, `std::queue` и `std::priority_queue` адаптируют контейнер под интерфейс LIFO, FIFO и приоритетной очереди. `std::map` и `std::set` обычно основаны на сбалансированном дереве и обеспечивают логарифмические операции и упорядоченный обход. `std::unordered_map` и `std::unordered_set` используют хеширование: средняя сложность поиска близка к O(1), но порядок обхода не определён, а худший случай может быть линейным.

Итератор обозначает позицию в последовательности. После вставки или удаления правила его действительности зависят от контейнера и операции. Не сохраняй итератор через операцию, которая может его инвалидировать.

## Разобранный пример

```cpp
#include <map>
#include <string>
#include <vector>

std::vector<int> samples{4, 2, 4};
std::map<std::string, int> counts;
for (int value : samples) ++counts[std::to_string(value)];
// Для большого числа поисков по ключу сравни map и unordered_map.
```

## Практика

1. **Задача:** Подбери контейнер для очереди задач, уникальных отсортированных ID и кэша по строковому ключу.
   - **Критерий проверки:** Для каждого выбора названы нужные операции и ожидаемая сложность.
   - **Подсказка:** Сравни queue, set/map и unordered_map.

2. **Задача:** Найди ошибку, где итератор `vector` используется после `push_back`.
   - **Критерий проверки:** Код не использует потенциально инвалидированный итератор.
   - **Подсказка:** Перераспределение памяти может изменить адреса элементов.

## Граничные случаи

- Инвалидация итераторов; отсутствие ключа; дубликаты; сложность худшего случая.

## Типичные ошибки

- Использовать `list` автоматически из-за частых вставок, не учитывая поиск позиции и кэш.
- Полагаться на порядок `unordered_map`.
- Считать, что все итераторы остаются действительными после модификации контейнера.
