# Threat modeling и безопасность

- **Трек:** Архитектура и эксплуатация
- **Модуль:** Надёжность и безопасность
- **Тип:** урок
- **ID:** `T10-M2-L2`

## Цель и критерий перехода

Объяснить контракт, инварианты, компромиссы и тесты; показать корректность на граничных случаях.

## Теория

Threat modeling начинается с определения активов, границ доверия и потенциальных атакующих действий. Не нужно сразу придумывать сложные схемы. Сначала ответь, какие данные защищаем, кто может передать ввод, какие компоненты имеют привилегии и что произойдёт при нарушении границы.

Недоверенный ввод должен проверяться на длину, формат, диапазоны и допустимые значения. При формировании пути учитывай path traversal. В SQL используй параметры, в сетевом протоколе ограничивай размеры, в распаковщике архивов проверяй путь и итоговый размер. Проверка только в UI не защищает серверный интерфейс.

Принцип least privilege означает, что компонент получает только необходимые права. Секреты не должны попадать в исходники, обычные логи и артефакты CI. Зависимости тоже входят в поверхность атаки. Обновления нужно проводить с учётом исправлений безопасности и совместимости.

## Разобранный пример

```text
Asset: пользовательские данные.
Entry points: API, импорт файла, SQL-параметры.
Threats: path traversal, oversized input, injection, секреты в логах.
Controls: allowlist пути, лимит размера, parameterized SQL, redaction.
Verification: негативные тесты и проверка логов.
```

Это минимальная модель угроз. Для каждой угрозы укажи вероятность, ущерб и проверяемую меру защиты.

## Практика

1. **Задача:** Проведи threat model для CLI, который импортирует путь к файлу и записывает данные в SQL.
   - **Критерий проверки:** Есть точки входа, активы, угрозы и тестируемые меры.
   - **Подсказка:** Проверь traversal, слишком большой файл и SQL injection.

2. **Задача:** Добавь тесты на огромную длину, некорректный путь и SQL-подобный ввод.
   - **Критерий проверки:** Программа безопасно отклоняет плохие данные и не раскрывает внутренние секреты.
   - **Подсказка:** Проверяй ошибки и побочные эффекты, а не только exit code.

3. **Задача:** Проверь, не попали ли секреты в логи и репозиторий.
   - **Критерий проверки:** Секреты удалены из истории/артефактов по соответствующей процедуре.
   - **Подсказка:** Простого удаления строки в последнем коммите может быть недостаточно.

## Граничные случаи

- Path traversal; injection; переполнение; утечка секретов.

## Типичные ошибки

- Валидировать ввод только на стороне интерфейса.
- Загружать любые архивные пути без нормализации.
- Считать внутреннюю сеть или локальную программу автоматически доверенной.

## Контрольные вопросы

1. Какое условие должно выполняться до вызова решения.
2. Что произойдёт на пустом или минимальном входе.
3. Какие тесты подтверждают корректность и какие ограничения остаются.
