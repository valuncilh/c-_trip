# Git и история изменений

- **Трек:** Инструменты и инженерная дисциплина
- **Модуль:** Рабочая среда
- **Тип:** урок
- **ID:** `T0-M1-L2`

## Цель и критерий перехода

Объяснить контракт, инварианты, компромиссы и тесты; показать корректность на граничных случаях.

## Теория

Git хранит снимки состояния проекта. Рабочее дерево содержит текущие файлы. Индекс определяет, что попадёт в следующий commit. Ветка — изменяемая ссылка на коммит, а не отдельная полная копия проекта.

Коммит должен фиксировать одну логическую перемену. Маленькие коммиты проще проверять и откатывать. `.gitignore` предотвращает случайное добавление сборочных результатов и локальных настроек.

Конфликт означает, что Git не смог автоматически совместить изменения. Прочитай обе стороны конфликта, восстанови намерение каждого изменения, затем запусти тесты.

## Разобранный пример

```bash
git status
git add src/main.cpp tests/main_test.cpp
git diff --cached
git commit -m "Add parser boundary tests"
git switch -c fix/parser-boundaries
```

`git diff --cached` показывает подготовленные изменения. Перед коммитом прочитай именно этот diff.

## Практика

1. **Задача:** Создай репозиторий и `.gitignore` для `build/`.
   - **Критерий проверки:** Сборочные файлы не отслеживаются.
   - **Подсказка:** Проверь `git status` после сборки.

2. **Задача:** Создай конфликт при merge и разреши его.
   - **Критерий проверки:** История корректна, маркеров конфликта не осталось, тесты проходят.
   - **Подсказка:** После разрешения прочитай файл целиком.

3. **Задача:** Подготовь один файл к коммиту, а другой оставь вне индекса.
   - **Критерий проверки:** `git diff` и `git diff --cached` отличаются.
   - **Подсказка:** Git разделяет рабочее дерево и индекс.

## Граничные случаи

- Незакоммиченные изменения; случайно добавленный бинарный файл.

## Типичные ошибки

- Коммитить build-каталог.
- Использовать разрушительный reset без проверки незакоммиченных файлов.
- Разрешать конфликт выбором стороны без понимания кода.

## Контрольные вопросы

1. Какое условие должно выполняться до вызова решения.
2. Что произойдёт на пустом или минимальном входе.
3. Какие тесты подтверждают корректность и какие ограничения остаются.
