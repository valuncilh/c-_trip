## Теория

### Перегрузка — несколько операций под одним именем

Перегрузка позволяет объявить несколько функций с одинаковым именем, но различающимися списками параметров. При вызове компилятор выбирает подходящую функцию на основании аргументов и правил разрешения перегрузки. Только различие в типе возвращаемого значения недостаточно: выражение вызова не выбирает функцию по тому, куда затем будет присвоен результат.

Перегрузки удобны, если операции действительно выражают одну идею для разных типов или наборов аргументов. Слишком много похожих перегрузок, неявных преобразований и значений по умолчанию может создать неоднозначный вызов. Проверяй сигнатуру, а не только имя.

### Аргументы по умолчанию

Значение по умолчанию позволяет опустить часть аргументов при вызове. Обычно оно указывается в объявлении, доступном вызывающему коду, и не является механизмом выбора реализации по возвращаемому типу. Не указывай значение по умолчанию повторно в другом объявлении той же функции в той же области видимости.

Если один интерфейс допускает слишком много комбинаций необязательных аргументов, может быть понятнее отдельная структура параметров или явные перегрузки. Цель — чтобы вызов читался без догадок о значении каждого аргумента.

### Рекурсия и два обязательных свойства

Рекурсивная функция вызывает сама себя. Для корректности нужны два свойства:

1. **Базовый случай** — вход, для которого ответ известен без нового рекурсивного вызова.
2. **Мера прогресса** — каждый рекурсивный шаг приближает аргумент к базовому случаю.

Без базового случая вызовы могут продолжаться до исчерпания стека. Наличие базового случая недостаточно, если рекурсивный шаг не уменьшает задачу. Для больших входов рекурсия также может потреблять много стека; цикл или явная структура данных иногда безопаснее.

### Переполнение — часть контракта

Математическое определение функции не гарантирует, что выбранный целочисленный тип способен вместить результат. Например, факториал быстро растёт, и вычисление в типе ограниченного диапазона может выйти за его пределы. Перед реализацией нужно определить допустимый диапазон и поведение за границей: ошибка, более широкий тип или другой алгоритм.

### Указатель на функцию и обобщённый вызываемый объект

Указатель на функцию может хранить адрес функции с подходящей сигнатурой и полезен для C API или простых таблиц обработчиков. Шаблонный параметр обычно подходит, когда вызываемый объект известен при компиляции и нужна оптимизация без стирания типа. `std::function<R(Args...)>` полезен, когда требуется хранить разные вызываемые объекты под единым интерфейсом, но у него могут быть дополнительные затраты из-за type erasure и копирования целевого объекта.

Не выбирай `std::function` автоматически для любого callback. Сначала определи, нужно ли хранить разные типы вызываемых объектов во время выполнения.

## Разобранный пример

```cpp
#include <iostream>

int area(int width, int height) {
    return width * height;
}

double area(double radius) {
    return 3.141592653589793 * radius * radius;
}

unsigned sum_digits(unsigned value) {
    if (value < 10) {
        return value;             // базовый случай, включая 0
    }
    return value % 10 + sum_digits(value / 10);
}

int main() {
    std::cout << area(3, 4) << '\n';
    std::cout << area(2.0) << '\n';
    std::cout << sum_digits(5024) << '\n';
}
```

`area(3, 4)` выбирает перегрузку прямоугольника по двум целочисленным аргументам, а `area(2.0)` — перегрузку круга с одним `double`. Функция `sum_digits` заканчивает рекурсию, когда значение стало однозначным. Для 0 она тоже сразу возвращает 0.

На каждом рекурсивном шаге `value / 10` уменьшает неотрицательное целое число, поэтому вызов приближается к базовому случаю. Результат не зависит от глобального состояния или порядка вызовов.

## Практика

### Задача 1. Перегрузи `print` для `int` и `std::string`.

**Критерий проверки.** Вызов выбирается по типу параметра, а не по возвращаемому типу.

> **Подсказка.** Различие должно быть в списке параметров.

### Задача 2. Реализуй сумму цифр числа итеративно и рекурсивно.

**Критерий проверки.** Варианты совпадают на 0, однозначных и многозначных неотрицательных числах.

> **Подсказка.** Рекурсивный шаг отделяет последнюю цифру через `% 10` и уменьшает число через `/ 10`.

### Задача 3. Для интерфейса с необязательным параметром объясни, безопасно ли значение по умолчанию.

**Критерий проверки.** Ты можешь прочитать вызов без догадок и исключил неоднозначные комбинации.

> **Подсказка.** Если параметров стало слишком много, попробуй структуру настроек вместо нескольких похожих перегрузок.

### Задача 4. Выбери между указателем на функцию, шаблонным параметром и `std::function` для трёх разных сценариев.

**Критерий проверки.** Решение обосновано тем, известен ли тип при компиляции и нужно ли хранить разные цели вызова.

> **Подсказка.** Учитывай не только удобство API, но и владение, время жизни и накладные затраты.

## Граничные случаи

- Вызов подходит нескольким перегрузкам.
- Неоднозначное преобразование типов.
- Нулевой аргумент для рекурсии.
- Рекурсивный шаг не уменьшает вход.
- Переполнение ограниченного целочисленного типа.
- Большая глубина вызовов.

## Типичные ошибки

- Пытаться перегрузить функцию только по возвращаемому типу.
- Задавать аргументы по умолчанию повторно или так, что несколько перегрузок подходят одному вызову.
- Забывать базовый случай рекурсии.
- Писать рекурсивный шаг, который не уменьшает задачу.
- Игнорировать переполнение целочисленного результата.
- Использовать `std::function` там, где достаточно шаблонного параметра или указателя на функцию.
