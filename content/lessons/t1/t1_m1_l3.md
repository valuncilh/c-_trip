## Теория

### Функция — именованная операция с интерфейсом

Функция группирует операцию под именем, чтобы её можно было вызывать из разных мест, проверять отдельно и описывать без деталей вызывающего кода. Её интерфейс включает имя, тип результата, параметры и правила вызова. Хорошая функция имеет одну понятную ответственность.

### Объявление и определение

Объявление сообщает компилятору сигнатуру: имя функции, тип результата и типы параметров. Определение содержит тело. Программа может использовать объявление до того, как компилятор увидит тело, но для итоговой сборки должно быть доступно соответствующее определение, если функция не является специальным случаем вроде шаблонного определения, доступного на месте инстанцирования.

### Параметры передаются по значению или по ссылке

При передаче по значению функция получает отдельный параметр. Изменение этого параметра не меняет исходную переменную вызывающей стороны. Для небольших числовых значений это обычно хороший вариант.

Ссылка позволяет функции обращаться к существующему объекту. Для чтения большого объекта часто используют константную ссылку `const T&`: она избегает копирования и обещает, что функция не будет менять объект через эту ссылку. Но ссылка не продлевает автоматически время жизни любого объекта, на который она указывает, поэтому нельзя возвращать ссылку на локальную переменную.

### Входной и выходной контракт

Контракт должен говорить, какие входы допустимы, что выдаёт функция и как она сообщает об ошибке. Например, период сигнала `T = 1 / f` имеет смысл только при конечной частоте `f > 0`. Если частота нулевая, отрицательная или не конечная, функция не должна молча возвращать правдоподобное число.

Предусловие описывает, что должно быть истинно до вызова; постусловие — что гарантируется при успешном возврате. Инвариант объекта — условие, которое объект поддерживает между публичными операциями. Такие формулировки помогают писать тесты на причины, а не только на примерные числа.

### Чистые функции проще проверять

Чистая функция зависит только от параметров, не меняет внешнее состояние и возвращает результат. Её проще тестировать, потому что повторный вызов с теми же входами не зависит от порядка тестов, времени или состояния файловой системы. Это не значит, что весь проект должен быть чистым: ввод-вывод лучше отделить от вычислительного ядра, чтобы проверять их независимо.

### Когда возвращать ошибку

Выбор зависит от контракта. Исключение подходит, когда переданные параметры нарушают предусловие и вызывающий код не может продолжить штатную операцию. `std::optional<T>` подходит, когда отсутствие результата является обычным исходом, например поиск не нашёл элемент. `std::expected` появился в C++23 и может выражать значение либо ошибку; если курс нацелен на C++20, не следует требовать его поддержки без дополнительного слоя совместимости.

## Разобранный пример

```cpp
#include <cmath>
#include <stdexcept>

bool is_valid_frequency(double hz) {
    return std::isfinite(hz) && hz > 0.0;
}

double period_seconds(double hz) {
    if (!is_valid_frequency(hz)) {
        throw std::invalid_argument("frequency must be finite and positive");
    }
    return 1.0 / hz;
}
```

Проверка выполняется до деления. Для частоты `1000 Hz` период равен `0.001 s`. Для нулевой частоты функция сообщает об ошибке, а не пытается скрыть деление на ноль.

У `is_valid_frequency` одна задача — проверить значение. У `period_seconds` другая — вычислить период, если вход разрешён. Разделение даёт независимые точки проверки и не привязывает вычислительную функцию к консольному вводу.

## Практика

### Задача 1. Напиши функцию преобразования температуры из градусов Цельсия в Фаренгейты.

**Критерий проверки.** Для 0 °C результат 32 °F; преобразование не читает stdin и не печатает stdout.

> **Подсказка.** Формула: `F = C × 9 / 5 + 32`. Следи за тем, чтобы 9 / 5 не вычислялось как целочисленное деление.

### Задача 2. Реализуй функцию, которая вычисляет период сигнала по частоте.

**Критерий проверки.** Положительная конечная частота даёт `T = 1/f`; ноль, отрицательная частота, NaN и бесконечность отклоняются.

> **Подсказка.** Проверяй `std::isfinite(f)` и `f > 0` до деления.

### Задача 3. Выбери тип результата для функции поиска: индекс или «не найдено».

**Критерий проверки.** Индекс 0 не смешивается с отсутствием результата; выбор типа объяснён контрактом.

> **Подсказка.** Нулевой индекс — действительный результат, поэтому одного целого числа недостаточно без отдельного соглашения.

## Граничные случаи

- Невалидный параметр до вычисления.
- Функция возвращает значение, которое может быть равно нулю.
- Передача большого объекта по значению.
- Возврат ссылки на объект с недостаточным временем жизни.
- Функция зависит от файла, часов или глобальной переменной.

## Типичные ошибки

- Смешивать ввод, вычисление и печать в одной функции, после чего нельзя проверить алгоритм без консоли.
- Забывать проверить предусловие до опасной операции.
- Возвращать ссылку на локальную переменную.
- Использовать ноль как признак «результат не найден», если ноль может быть корректным результатом.
- Называть функцию общей, хотя она неявно зависит от глобального состояния.
