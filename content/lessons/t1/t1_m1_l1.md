# Типы, значения и преобразования

- **Трек:** undefined
- **Модуль:** undefined
- **Тип:** урок
- **ID:** `T1-M1-L1`

## Цель и критерий освоения

Ты умеешь предсказывать тип и результат выражения, отличать целочисленное деление от вещественного, проверять диапазон перед преобразованием и объяснять, почему вычисления с double могут иметь погрешность.

## Перед началом

- Понимать, что такое переменная и простое выражение.
- Уметь собрать короткую программу C++20.

## Теория

### Тип — часть контракта значения

Переменная — именованное место, в котором программа хранит значение определённого типа. Тип задаёт множество допустимых значений, размер и представление в рамках реализации, а также правила операций. Например, `int` предназначен для целых чисел, `double` — для приближённых вещественных вычислений, `bool` — для логических значений.

Выбирай тип по смыслу величины, диапазону и требуемой точности. Количество отсчётов естественно хранить в целочисленном типе, а длительность с дробной частью — в вещественном. Но тип сам по себе не проверяет входные данные: пользователь всё ещё может ввести отрицательное число, бесконечность или значение вне разрешённого диапазона.

### Результат выражения зависит от операндов

В выражении `7 / 2` оба операнда — целые числа, поэтому дробная часть результата отбрасывается. Получится `3`. В выражении `7.0 / 2` один операнд имеет тип `double`, поэтому второй преобразуется для вещественного деления и результат равен `3.5`. Это происходит до печати результата: форматирование вывода не вернёт уже потерянную дробную часть.

При смешивании числовых типов компилятор применяет правила стандартных арифметических преобразований. Они удобны, но не всегда совпадают с интуицией, особенно при смешивании знаковых и беззнаковых целых чисел. Явный `static_cast<T>` полезен, когда намерение стоит показать читателю, но он не заменяет проверку, что значение вообще помещается в целевой тип.

### Диапазон и сужающие преобразования

Сужающее преобразование может потерять часть значения — например, дробную часть при переводе вещественного числа в целое или значащие биты при переводе в более узкий тип. Фигурная инициализация, например `int count{12};`, запрещает некоторые сужающие преобразования и позволяет обнаружить ошибку при компиляции.

Перед преобразованием внешнего ввода проверь контракт. Если допустимы только значения от 0 до 1 000 000, отвергни значения за пределами этого интервала до того, как приводить их к узкому типу. Нельзя считать, что любой вход автоматически валиден.

### Знаковые и беззнаковые целые

Знаковые целые представляют отрицательные и положительные значения. Беззнаковые целые — только неотрицательные; их арифметика определена по модулю диапазона типа. Например, вычитание 1 из беззнакового нуля даёт максимальное значение этого типа, а не отрицательную единицу.

Это особенно важно для размеров контейнеров: `std::size_t` обычно используется для количества элементов и индексов, но выражение `size - 1` некорректно как способ получить «последний индекс» пустого контейнера. Сначала нужно проверить пустоту.

Переполнение знакового целого в C++ — неопределённое поведение. Не полагайся на циклический переход через максимум для знаковых счётчиков. Если диапазон может быть превышен, используй проверку до сложения или умножения.

### Вещественные числа приближённые

`double` обычно хранит двоичное приближение числа. Многие десятичные дроби, включая 0.1, нельзя представить точно конечной двоичной дробью. Поэтому результат вычисления может немного отличаться от математического значения, и прямое сравнение двух независимо вычисленных значений через `==` часто не выражает нужный смысл.

Для сравнения используют допуск, который соответствует масштабу величины и требованиям задачи. Абсолютная погрешность:

$$
\varepsilon_{abs}=|x-\hat{x}|
$$

Относительная погрешность при `x ≠ 0`:

$$
\varepsilon_{rel}=\frac{|x-\hat{x}|}{|x|}
$$

Здесь `x` — эталонное значение, а `x̂` — вычисленное. Абсолютный допуск полезен при фиксированном масштабе; относительный — при сравнении величин разного порядка. Конкретный предел нельзя выбирать наугад: для инженерного измерения он определяется требованиями к системе, а не универсальным правилом языка C++.

## Разобранный пример

```cpp
#include <iostream>

int main() {
    int count{12};
    double interval_seconds{0.25};

    double duration =
        static_cast<double>(count) * interval_seconds;

    int integer_division = 7 / 2;
    double floating_division = 7.0 / 2;

    std::cout << "duration = " << duration << " s\n";
    std::cout << "7 / 2 = " << integer_division << '\n';
    std::cout << "7.0 / 2 = " << floating_division << '\n';
}
```

Результат:

```text
duration = 3 s
7 / 2 = 3
7.0 / 2 = 3.5
```

`count` — количество интервалов, а `interval_seconds` — длительность одного интервала. Размерность выражения: «интервалы × секунды на интервал = секунды». `static_cast<double>` здесь подчёркивает переход к вещественному вычислению, хотя при умножении на `double` язык и без него преобразовал бы `count`.

## Практика

### Задача 1. Напиши конвертер миллисекунд в секунды с дробной частью.

**Критерий проверки.** Ввод `1500` даёт `1.5` секунды; значения меньше одной секунды тоже сохраняют дробную часть.

> **Подсказка.** Не выполняй целочисленное деление на 1000.

### Задача 2. Проверь вход перед преобразованием в целочисленный тип: разрешены только значения от 0 до заданного предела.

**Критерий проверки.** Отрицательное значение и значение выше предела отклоняются до преобразования.

> **Подсказка.** Сначала определи контракт диапазона, затем выбирай способ преобразования.

### Задача 3. Сравни два значения `double` с допуском для величин разного масштаба.

**Критерий проверки.** Ты можешь объяснить, почему выбран абсолютный или относительный допуск и откуда взялось его значение.

> **Подсказка.** Один фиксированный допуск может быть слишком большим для маленькой величины и слишком строгим для большой.

## Граничные случаи

- Дробная часть теряется при переводе в целое.
- Значение выходит за диапазон целевого типа.
- Смешиваются signed и unsigned.
- Деление на ноль.
- NaN и бесконечность.
- Масштаб входных величин сильно меняется.

## Типичные ошибки

- Ожидать, что `7 / 2` станет 3.5 из-за того, что результат печатается с дробной частью.
- Считать `static_cast` проверкой диапазона — преобразование не проверяет, соответствует ли исходное значение требованиям.
- Использовать вычитание беззнаковых величин и ожидать отрицательный результат.
- Считать, что знаковое целое переполняется предсказуемым циклическим образом.
- Сравнивать вычисленные `double` через `==` без понимания требуемого допуска.
