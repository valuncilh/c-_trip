# Проект C — многопоточный сетевой сервис

- **Трек:** Проектная лаборатория
- **Модуль:** Интеграционные проекты
- **Тип:** project
- **ID:** `T11-M1-L3`

## Цель и критерий перехода

Объяснить контракт, инварианты, компромиссы и тесты; показать корректность на граничных случаях.

## Теория

Сделай сервис, который принимает TCP-запросы, разбирает framing, выполняет операции и возвращает ответы. Выдели протокол, transport, бизнес-логику и хранилище. Потоки не должны напрямую обращаться к общему состоянию без модели синхронизации. Количество одновременно выполняемых задач должно быть ограничено.

TCP передаёт поток байтов, поэтому тесты обязаны разделять заголовок и тело на произвольные фрагменты. Проверяй disconnect посреди сообщения, oversized frame, медленного клиента и ошибку базы. Сервис должен иметь таймауты, ограничение очереди, backpressure и понятную политику остановки.

Нагрузочный тест измеряет latency и throughput, но также должен проверять корректность ответов и ошибки. Система, которая быстро принимает соединения, но копит бесконечную очередь и исчерпывает память, не является надёжной.

## Разобранный пример

```text
Listener
  -> Connection handler
  -> Frame decoder and input limit
  -> Bounded task queue
  -> Worker pool
  -> Application service
  -> SQL repository
  -> Response encoder
```

Это ориентир, а не обязательная архитектура. Для небольшого сервиса можно объединить слои, если границы остаются понятными и тестируемыми.

## Практика

1. **Задача:** Реализуй length-prefixed протокол с лимитом размера и корректным чтением.
   - **Критерий проверки:** Работает при частичном заголовке, частичном payload и разрыве соединения.
   - **Подсказка:** Не предполагай, что один `recv` заполняет буфер полностью.

2. **Задача:** Добавь ограниченную очередь и стратегию backpressure.
   - **Критерий проверки:** При перегрузке система отклоняет или задерживает запросы предсказуемо.
   - **Подсказка:** Очередь не должна расти бесконечно.

3. **Задача:** Реализуй безопасную остановку, которая не освобождает данные раньше worker-потоков.
   - **Критерий проверки:** Сервис завершается в предсказуемое время.
   - **Подсказка:** Сначала прекрати приём новой работы, затем останови и дождись workers.

4. **Задача:** Запусти TSan, интеграционные тесты и нагрузочный профиль.
   - **Критерий проверки:** Нет известных гонок в покрывающих сценариях, показатели и методика сохранены.
   - **Подсказка:** Sanitizer не заменяет нагрузочный тест, а нагрузка не заменяет тесты корректности.

## Граничные случаи

- Нет data race в поддерживаемой конфигурации TSan; retry ограничен.

## Типичные ошибки

- Считать TCP-сообщения равными вызовам recv.
- Не ограничивать размер очереди или фрейма.
- Уничтожать общие объекты до завершения рабочих потоков.

## Контрольные вопросы

1. Какое условие должно выполняться до вызова решения.
2. Что произойдёт на пустом или минимальном входе.
3. Какие тесты подтверждают корректность и какие ограничения остаются.
