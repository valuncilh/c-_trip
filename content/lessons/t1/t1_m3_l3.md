## Теория

### У разных последовательностей разные контракты

Встроенный массив имеет размер, зафиксированный в его типе. Например, `int samples[4]` содержит четыре элемента с индексами 0, 1, 2 и 3. Он не хранит отдельный доступный метод `size()` для обычного массива и не меняет размер при добавлении новых значений.

В прикладном C++ часто удобнее стандартные типы, потому что они явно выражают назначение:

- `std::array<T, N>` — владеющий контейнер с фиксированным размером `N`; он знает размер и совместим с алгоритмами STL.
- `std::vector<T>` — последовательность переменного размера с динамическим управлением памятью.
- `std::string` — владеющий текстовый буфер с удобными операциями над строкой.
- `std::span<T>` — невладеющее представление непрерывного диапазона; оно передаёт указатель и размер вместе, но не продлевает время жизни исходных данных.

Выбирай контейнер по контракту. Не начинай с сырого массива только потому, что он короче на одну строку.

### Индексация и границы

У последовательности из `N` элементов допустимы индексы от 0 до `N - 1`, если `N > 0`. Условие обхода обычно пишется как `i < values.size()`. Условие `i <= values.size()` включает позицию за последним элементом и может привести к неопределённому поведению.

Не путай количество элементов с количеством зарезервированных мест: у `std::vector` метод `size()` возвращает число существующих элементов, а `capacity()` — вместимость без обязательного перераспределения. Для встроенного массива размер фиксирован самим типом.

### Массивы в параметрах функций

Когда встроенный массив передаётся параметром, его тип в объявлении функции обычно преобразуется в указатель на первый элемент. Функция не получает размер массива автоматически. Поэтому функции с параметром вида `int values[]` должны получать размер отдельным параметром, иначе они не могут надёжно определить границу.

В C++20 для непрерывного диапазона часто удобен `std::span<const T>`: он передаёт указатель и длину вместе и выражает доступ только для чтения. Но span не владеет данными: нельзя сохранять его дольше, чем живёт исходный массив или контейнер.

### Многомерные массивы

Встроенный двумерный массив — это массив массивов. В `int grid[rows][cols]` внешний индекс выбирает строку, внутренний — элемент внутри строки. Элементы расположены построчно, поэтому при полном обходе естественно использовать внешний цикл по строкам, внутренний — по столбцам.

Размерности влияют на тип: массив с фиксированным числом столбцов не эквивалентен произвольному указателю на указатель. Для динамического количества строк и столбцов проще выбрать контейнеры, контракт которых соответствует данным, например вектор векторов или плоский вектор с явно заданным числом столбцов.

### C-строка и std::string

C-строка — это последовательность символов `char`, завершающаяся нулевым байтом `'\0'`. В объявлении `char id[] = "A1";` память содержит три элемента: `'A'`, `'1'` и завершающий ноль. Поэтому буфер для текста длины `N` требует места как минимум для `N + 1` байтов, если используется C-строковый контракт.

Произвольный массив `char buffer[8]` сам по себе не становится корректной C-строкой: в нём может не быть нулевого терминатора. Передача такого массива функции, ожидающей C-строку, может привести к чтению за границами буфера. Для обычного владения текстом используй `std::string`, а C-строки оставляй для границ с C API и форматами, где они действительно требуются.

Байты `std::string` не равны универсально пользовательским символам: в UTF-8 одна кодовая точка может занимать несколько байтов. Для обработки Unicode нужно понимать кодировку, а не просто считать `size()` числом отображаемых символов.

## Разобранный пример

```cpp
#include <array>
#include <iostream>
#include <span>
#include <string>

int sum(std::span<const int> values) {
    int result = 0;
    for (int value : values) {
        result += value;
    }
    return result;
}

int main() {
    std::array<int, 3> readings{4, 1, 9};
    std::cout << sum(readings) << '\n';

    std::string name = "sensor-01";
    char c_id[] = "A1";
    std::cout << name.size() << '\n';
    std::cout << sizeof(c_id) << '\n';
}
```

Для массива `readings` функция `sum` получает диапазон вместе с размером, поэтому не требует отдельного параметра длины. Результат суммы — `14`, размер строки `sensor-01` равен 9 байтам, а `sizeof(c_id)` равен 3: два печатных символа и нулевой терминатор.

`std::span` не копирует значения и не владеет ими. Здесь это безопасно, потому что `readings` живёт дольше вызова `sum`. Не сохраняй такой span для использования после уничтожения исходного контейнера.

## Практика

### Задача 1. Напиши функцию, которая возвращает сумму элементов через §std::span<const int>§.

**Критерий проверки.** Функция корректно обрабатывает пустой диапазон и не меняет исходные элементы.

> **Подсказка.** При пустом диапазоне цикл не выполнится, и сумма останется равной нулю.

### Задача 2. Вычисли сумму каждой строки матрицы 3 × 4.

**Критерий проверки.** Обработаны все 12 элементов; индексы строки и столбца остаются в допустимых пределах.

> **Подсказка.** Внешний цикл проходит строки, внутренний — столбцы.

### Задача 3. Преобразуй функцию, принимающую C-строку, в функцию со §std::string§.

**Критерий проверки.** Нет ручного поиска конца строки и записи за пределы буфера.

> **Подсказка.** Используй §size()§, §empty()§ и безопасный интерфейс строки.

### Задача 4. Объясни, почему §std::span§ нельзя сохранять после уничтожения исходного вектора.

**Критерий проверки.** В ответе различаются владение данными и представление диапазона.

> **Подсказка.** Span хранит описание диапазона, но не продлевает жизнь памяти.

## Граничные случаи

- Пустой диапазон.
- Один элемент и последний допустимый индекс.
- Матрица с одной строкой или одним столбцом.
- Отсутствующий нулевой терминатор у C-строки.
- Попытка использовать span после уничтожения владельца.
- Unicode-текст с многобайтовыми кодовыми точками.

## Типичные ошибки

- Писать условие обхода §i <= values.size()§ вместо §i < values.size()§.
- Считать, что размер встроенного массива автоматически передаётся функции как часть параметра.
- Путать §reserve§ с созданием элементов и путать размер с ёмкостью.
- Предполагать, что любой массив char уже содержит C-строку с терминатором.
- Хранить §std::span§ дольше исходного массива или контейнера.
- Считать §std::string::size()§ количеством видимых пользовательских символов в UTF-8.
