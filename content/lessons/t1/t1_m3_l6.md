- **ID:** `T1-M3-L6`

## Цель и критерий перехода

Формулировать инвариант класса и выбирать Rule of Zero вместо ручного управления ресурсом без необходимости.

## Теория

Класс объединяет состояние и операции над ним. Инвариант — условие, которое должно быть истинным у каждого полностью созданного объекта. Конструктор обязан установить инвариант, а публичные методы не должны его нарушать. Поля обычно инициализируют в списке инициализации: так объект сразу создаётся в нужном состоянии.

Деструктор вызывается при завершении времени жизни объекта и освобождает принадлежащие ему ресурсы. Если класс использует стандартные RAII-типы (`std::string`, `std::vector`, `std::unique_ptr`), чаще всего не нужно писать собственные конструктор копирования, оператор присваивания или деструктор — это Rule of Zero.

Если класс сам владеет сырым ресурсом, копирование по умолчанию может привести к двойному освобождению или совместному владению без правил. В таком случае нужно продумать семантику копирования и перемещения либо заменить сырой ресурс подходящим RAII-типом.

## Разобранный пример

```cpp
#include <stdexcept>
#include <string>

class Device {
public:
    Device(std::string name, int channel)
        : name_(std::move(name)), channel_(channel) {
        if (channel_ < 0) throw std::invalid_argument("channel");
    }
    const std::string& name() const { return name_; }
    int channel() const { return channel_; }
private:
    std::string name_;
    int channel_;
};
```

## Практика

1. **Задача:** Спроектируй `Range`, у которого нижняя граница не больше верхней.
   - **Критерий проверки:** Некорректное состояние нельзя создать через публичный интерфейс.
   - **Подсказка:** Проверь параметры в конструкторе.

2. **Задача:** Объясни, почему класс с `std::vector<int>` обычно не нуждается в ручном деструкторе.
   - **Критерий проверки:** В ответе упомянуты владение и автоматическое управление ресурсом.
   - **Подсказка:** Контейнер уже отвечает за память своих элементов.

## Граничные случаи

- Частично инициализированный объект; исключение в конструкторе; копирование владеющего ресурса.

## Типичные ошибки

- Делать все поля публичными и терять контроль над инвариантом.
- Выделять память вручную, когда достаточно стандартного контейнера.
- Писать деструктор, не продумав копирование и перемещение.
