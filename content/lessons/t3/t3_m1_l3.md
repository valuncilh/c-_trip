# Копирование, move и forwarding

- **Трек:** Современный C++ и ресурсы
- **Модуль:** Время жизни и объектная модель
- **Тип:** урок
- **ID:** `T3-M1-L3`

## Цель и критерий перехода

Объяснить контракт, инварианты, компромиссы и тесты; показать корректность на граничных случаях.

## Теория

Категория выражения влияет на выбор перегрузки. `std::move` сам ничего не перемещает. Он преобразует выражение, после чего выбранный конструктор или оператор присваивания может переместить ресурс.

Перемещение часто передаёт внутренний буфер вместо копирования всех элементов. Но перемещение не всегда быстрее копирования. Перемещённый объект остаётся допустимым для уничтожения и ряда операций, но его значение зависит от типа. Не предполагай, что строка после move всегда пустая.

Forwarding reference встречается в шаблонных контекстах с выводом `T&&`. `std::forward<T>` сохраняет категорию исходного аргумента. Это важно для generic-обёрток. Это не общий способ ускорить код. Сначала нужны корректные контракты, затем измерение.

## Разобранный пример

```cpp
#include <string>
#include <utility>

std::string greet(std::string name) {
    return "Hello, " + name;
}

int main() {
    std::string name = "Ada";
    std::string message = greet(std::move(name));
}
```

После move `name` остаётся живым объектом, но не следует предполагать, что его значение осталось прежним. Его можно присвоить заново или уничтожить.

## Практика

1. **Задача:** Добавь логирование копирующего и перемещающего конструктора собственного типа.
   - **Критерий проверки:** Видно, когда вызывается копирование и когда move.
   - **Подсказка:** Сравни lvalue и выражение с `std::move`.

2. **Задача:** Сделай forwarding-обёртку, которая передаёт аргумент дальше.
   - **Критерий проверки:** Lvalue/rvalue-перегрузки остаются различимыми.
   - **Подсказка:** Используй `T&&` с выводимым T и `std::forward<T>`.

3. **Задача:** Повторно используй перемещённый объект безопасным способом.
   - **Критерий проверки:** Код не опирается на конкретное moved-from значение.
   - **Подсказка:** Присвой объекту новое значение до чтения.

## Граничные случаи

- std::move(const T); самоприсваивание; исключение при присваивании.

## Типичные ошибки

- Считать `std::move` самостоятельным перемещением.
- Ожидать обычный move из `const`-объекта.
- Использовать moved-from значение как будто оно не менялось.
