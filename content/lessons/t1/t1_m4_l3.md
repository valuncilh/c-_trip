# Исключения и гарантии безопасности

- **Трек:** Основы программирования и C++
- **Модуль:** Объектная модель и стандартная библиотека
- **Тип:** урок
- **ID:** `T1-M4-L3`

## Цель и критерий перехода

Не терять диагностику и не оставлять объект или систему в нарушенном состоянии при ошибке.

## Теория

Исключение сообщает, что операция не смогла выполнить обычный контракт. Оно распространяется по стеку вызовов до подходящего `catch`; при раскрутке стека деструкторы уже созданных локальных объектов вызываются автоматически. Поэтому RAII особенно важен для корректной очистки ресурсов при ошибках.

Перехватывай исключения по `const`-ссылке, когда нет причины копировать объект. Не перехватывай всё подряд и не скрывай ошибку пустым `catch`. Выбирай тип исключения, который помогает вызывающему коду понять проблему. Не используй исключения для обычного управления циклом.

Полезно различать гарантии: отсутствие утечек ресурсов; базовая гарантия — объект остаётся корректным, но его значение может измениться; сильная гарантия — операция либо завершается полностью, либо не меняет наблюдаемое состояние. Интерфейс должен ясно определять, какие ошибки возможны.

## Разобранный пример

```cpp
#include <fstream>
#include <stdexcept>

void load(const char* path) {
    std::ifstream file(path);
    if (!file) throw std::runtime_error("cannot open input file");
    // file автоматически закроется при выходе из области видимости
}

try {
    load("config.txt");
} catch (const std::exception& e) {
    // записать диагностику и выбрать политику восстановления
}
```

## Практика

1. **Задача:** Напиши функцию, которая открывает файл и сообщает об ошибке через исключение.
   - **Критерий проверки:** Файл закрывается автоматически и ошибка не теряется.
   - **Подсказка:** Используй `std::ifstream` и RAII.

2. **Задача:** Найди пустой `catch (...)` и замени его осмысленной обработкой.
   - **Критерий проверки:** Ошибка либо обрабатывается, либо передаётся выше.
   - **Подсказка:** Сначала реши, кто отвечает за восстановление.

## Граничные случаи

- Исключение в конструкторе; повторный throw; частично выполненная операция.

## Типичные ошибки

- Перехватывать исключение и молча продолжать работу.
- Бросать исключения из деструктора при обычном разрушении объекта.
- Считать `catch (...)` универсальным способом исправления ошибок.
