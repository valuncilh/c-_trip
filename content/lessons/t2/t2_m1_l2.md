# Стек, очередь, deque и список

- **Трек:** Алгоритмы и структуры данных
- **Модуль:** Базовые структуры и сложность
- **Тип:** урок
- **ID:** `T2-M1-L2`

## Цель и критерий перехода

Объяснить контракт, инварианты, компромиссы и тесты; показать корректность на граничных случаях.

## Теория

Стек обслуживает последний добавленный элемент первым. Очередь — первый добавленный первым. `deque` поддерживает эффективные операции на обоих концах. Связный список хранит отдельные узлы, соединённые ссылками. Вставка известного узла может быть дёшевой, но поиск места для вставки обычно линейный.

Выбор структуры зависит от реальных операций. `std::vector` часто быстрее списка при обходе благодаря непрерывной памяти и меньшим накладным расходам. Список оправдан, когда важны его специфические свойства, например стабильность итераторов при определённых вставках.

Для каждой структуры проверь пустое состояние, удаление единственного элемента и повторное удаление. Контракт должен определить поведение операции, если элемент отсутствует.

## Разобранный пример

```cpp
#include <stack>
#include <string>

bool balanced(const std::string& text) {
    std::stack<char> opened;
    for (char ch : text) {
        if (ch == '(') opened.push(ch);
        else if (ch == ')') {
            if (opened.empty()) return false;
            opened.pop();
        }
    }
    return opened.empty();
}
```

Пример проверяет только круглые скобки. Чтобы поддерживать `[]` и `{}`, нужно хранить тип открывающей скобки и проверять соответствие.

## Практика

1. **Задача:** Реализуй очередь через `std::deque`.
   - **Критерий проверки:** Пустая очередь не отдаёт несуществующий элемент молча.
   - **Подсказка:** Определи поведение `pop` и `front` для пустого контейнера.

2. **Задача:** Расширь проверку скобок для `()`, `[]` и `{}`.
   - **Критерий проверки:** Лишняя закрывающая и несовпадающая скобка отклоняются.
   - **Подсказка:** Сверяй закрывающую скобку с вершиной стека.

3. **Задача:** Выбери структуру для очереди задач с добавлением в конец и удалением из начала.
   - **Критерий проверки:** Обоснование включает сложность и свойства инвалидирования.
   - **Подсказка:** Сравни `deque` и `vector`.

## Граничные случаи

- Пустая структура; удаление последнего элемента; нехватка памяти.

## Типичные ошибки

- Считать список всегда быстрее вектора.
- Удалять из начала `vector` в интенсивном цикле без оценки стоимости.
- Не определять поведение пустой структуры.
