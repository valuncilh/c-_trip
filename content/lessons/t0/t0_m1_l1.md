# Терминал, файлы и процессы

- **Трек:** Инструменты и инженерная дисциплина
- **Модуль:** Рабочая среда
- **Тип:** урок
- **ID:** `T0-M1-L1`

## Цель и критерий перехода

Объяснить контракт, инварианты, компромиссы и тесты; показать корректность на граничных случаях.

## Теория

Терминал запускает программы через оболочку. Команда состоит из имени программы и отдельных аргументов. Кавычки нужны, когда один аргумент содержит пробелы. Переменные окружения влияют на поиск программ и настройки инструментов.

Процесс возвращает код завершения. Обычно ноль означает успех, ненулевое значение — ошибку. stdout предназначен для результата, stderr — для диагностики. Их можно сохранить отдельно или передать вывод одной команды другой через конвейер.

Относительный путь считается от текущего каталога. Перед удалением или перезаписью файла проверь текущий каталог и точный путь.

## Разобранный пример

```bash
pwd
mkdir -p demo/src demo/build
printf 'hello\n' > demo/src/input.txt
grep hello demo/src/input.txt
```

`mkdir -p` создаёт промежуточные каталоги. `>` перезаписывает файл, а `>>` дописывает в конец.

## Практика

1. **Задача:** Создай каталоги `src`, `include`, `tests`, `build` и README.
   - **Критерий проверки:** Все файлы находятся в ожидаемых местах.
   - **Подсказка:** Используй `mkdir -p` и проверь дерево.

2. **Задача:** Сохрани stdout и stderr команды в разные файлы.
   - **Критерий проверки:** Потоки не смешаны, код завершения можно проверить.
   - **Подсказка:** Проверь `$?` сразу после команды.

3. **Задача:** Найди все `.cpp`, исключив каталог сборки.
   - **Критерий проверки:** Вывод содержит исходники, но не объектные файлы из build.
   - **Подсказка:** Используй `find` с исключением каталога.

## Граничные случаи

- Путь с пробелами; отсутствующий файл; ненулевой код завершения.

## Типичные ошибки

- Считать, что любая команда печатает только полезный результат.
- Забывать, что `>` перезаписывает файл.
- Удалять данные, не проверив текущий каталог.
