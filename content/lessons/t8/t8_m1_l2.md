# SELECT, JOIN и аналитика

- **Трек:** SQL и хранение данных
- **Модуль:** Реляционная модель
- **Тип:** урок
- **ID:** `T8-M1-L2`

## Цель и критерий перехода

Объяснить контракт, инварианты, компромиссы и тесты; показать корректность на граничных случаях.

## Теория

SQL описывает, какие данные нужны, а не пошаговую процедуру их получения. `WHERE` фильтрует строки, `GROUP BY` формирует группы, агрегаты рассчитывают значения по группе, а `HAVING` фильтрует уже агрегированные группы. `JOIN` соединяет таблицы по условию. Ошибка в условии соединения может незаметно умножить строки и испортить суммы.

Оконные функции позволяют рассчитать значение относительно соседних строк, не сводя их в одну строку группы. Например, `ROW_NUMBER` может пронумеровать события внутри каждого пользователя. `ORDER BY` внутри окна должен быть определён достаточно точно, если требуется стабильный выбор последней записи.

План запроса помогает понять, как база читает таблицы и использует индексы. Сначала добейся правильного результата на данных с дубликатами, NULL и пустыми таблицами. Только затем оптимизируй его по плану и измерениям.

## Разобранный пример

```sql
SELECT user_id,
       COUNT(*) AS completed_count
FROM lesson_progress
WHERE completed = TRUE
GROUP BY user_id
HAVING COUNT(*) >= 5
ORDER BY completed_count DESC;
```

`WHERE` убирает незавершённые записи до группировки. `HAVING` оставляет группы с пятью или более завершёнными уроками. Если связь таблиц создаёт дубликаты, счётчик может не соответствовать числу уникальных уроков.

## Практика

1. **Задача:** Составь запрос на список курсов и количество уроков в каждом.
   - **Критерий проверки:** Курс без уроков тоже присутствует, если это часть требований.
   - **Подсказка:** Подумай, нужен ли `LEFT JOIN`.

2. **Задача:** Найди последнее событие каждого пользователя.
   - **Критерий проверки:** При одинаковых timestamp результат детерминирован.
   - **Подсказка:** Добавь дополнительный ключ для разрешения равенства.

3. **Задача:** Сравни сумму до и после JOIN таблицы, в которой есть дубликаты.
   - **Критерий проверки:** Ты объясняешь, почему JOIN умножил строки.
   - **Подсказка:** Проверь уникальность ключа соединения.

## Граничные случаи

- JOIN умножает строки; NULL в агрегатах; ties в ranking.

## Типичные ошибки

- Считать, что JOIN всегда сохраняет количество строк.
- Использовать `WHERE` вместо `HAVING` для условия по агрегату.
- Не задавать tie-break для выбора последней строки.
