# Процессы, дескрипторы и IPC

- **Трек:** Системное программирование и сети
- **Модуль:** ОС и сеть
- **Тип:** урок
- **ID:** `T9-M1-L1`

## Цель и критерий перехода

Объяснить контракт, инварианты, компромиссы и тесты; показать корректность на граничных случаях.

## Теория

Процесс имеет собственное виртуальное адресное пространство. Потоки одного процесса разделяют память, а процессы обычно взаимодействуют через IPC: каналы, сокеты, разделяемую память или другие механизмы ОС. Системные вызовы могут завершаться ошибками, которые надо проверять.

Чтение и запись файловых дескрипторов могут быть частичными. Успешный `write` не всегда означает, что все переданные байты были записаны. Системный вызов может быть прерван сигналом. Поэтому обёртка должна обрабатывать partial I/O, `EINTR` и другие ошибки в соответствии с контрактом.

RAII полезен для дескрипторов ОС. Владеющий объект должен закрывать дескриптор ровно один раз. Нельзя просто копировать целое число дескриптора в два объекта-владельца, иначе оба могут попытаться закрыть один ресурс.

## Разобранный пример

```cpp
// Псевдокод алгоритма полной записи, не готовая переносимая реализация.
// while (remaining > 0) {
//     n = write(fd, data, remaining);
//     if (n > 0) advance(data, n);
//     else if (errno == EINTR) continue;
//     else return error;
// }
```

Системные API отличаются между ОС. Для реального кода используй документацию целевой платформы и учитывай ошибки, которые конкретный вызов может вернуть.

## Практика

1. **Задача:** Реализуй RAII-владельца файлового дескриптора без двойного закрытия.
   - **Критерий проверки:** Копирование запрещено либо определяет безопасную семантику.
   - **Подсказка:** Для владения обычно подходит move-only тип.

2. **Задача:** Обработай partial read/write и прерывание системного вызова.
   - **Критерий проверки:** Все байты обрабатываются или возвращается чёткая ошибка.
   - **Подсказка:** Один вызов не обязан обработать весь буфер.

3. **Задача:** Передай сообщение между двумя процессами через IPC.
   - **Критерий проверки:** Закрытие одного конца канала и раннее завершение процесса обработаны.
   - **Подсказка:** Проверь EOF и ошибку записи в закрытый канал.

## Граничные случаи

- EINTR; partial I/O; закрытый дескриптор; signal safety.

## Типичные ошибки

- Предполагать, что read/write обрабатывает весь буфер.
- Не проверять код ошибки системного вызова.
- Создавать несколько владельцев одного дескриптора.
