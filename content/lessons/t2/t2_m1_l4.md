# Сортировка и бинарный поиск

- **Трек:** Алгоритмы и структуры данных
- **Модуль:** Базовые структуры и сложность
- **Тип:** урок
- **ID:** `T2-M1-L4`

## Цель и критерий перехода

Объяснить контракт, инварианты, компромиссы и тесты; показать корректность на граничных случаях.

## Теория

Сортировка упорядочивает элементы по выбранному правилу. Компаратор должен задавать строгий слабый порядок. Например, `comp(x, x)` должен возвращать `false`. Противоречивый компаратор нарушает требования стандартных алгоритмов.

Бинарный поиск применяют к диапазону, уже упорядоченному по совместимому правилу. На каждом шаге он исключает половину оставшегося диапазона, поэтому количество сравнений растёт как `O(log n)`. `lower_bound` возвращает первый элемент, который не меньше искомого значения. Если точного совпадения нет, это всё равно полезная позиция вставки.

Полуоткрытый диапазон `[first, last)` включает начало, но не включает конец. Он может быть пустым при `first == last`, поэтому упрощает работу с границами.

## Разобранный пример

```cpp
#include <algorithm>
#include <vector>

int main() {
    const std::vector<int> values{1, 2, 2, 2, 5, 8};
    auto it = std::lower_bound(values.begin(), values.end(), 2);
    return (it - values.begin()) == 1 ? 0 : 1;
}
```

Первый элемент, равный `2`, находится по индексу `1`. При отсутствии искомого значения результатом будет позиция вставки.

## Практика

1. **Задача:** Реализуй бинарный поиск в полуоткрытом диапазоне.
   - **Критерий проверки:** Пустой диапазон и крайние позиции корректны.
   - **Подсказка:** Поддерживай инвариант границ поиска.

2. **Задача:** Найди первое вхождение значения среди дубликатов.
   - **Критерий проверки:** Возвращается минимальный индекс совпадения.
   - **Подсказка:** Используй `lower_bound`.

3. **Задача:** Сортируй по убыванию и реализуй совместимый поиск.
   - **Критерий проверки:** Компаратор при сортировке и поиске согласован.
   - **Подсказка:** Обычный `lower_bound` не следует автоматически применять к диапазону, отсортированному по обратному порядку.

## Граничные случаи

- Дубликаты; пустой диапазон; некорректный компаратор.

## Типичные ошибки

- Искать в неотсортированном диапазоне.
- Использовать `<=` в компараторе сортировки.
- Считать `lower_bound` поиском только существующих элементов.
