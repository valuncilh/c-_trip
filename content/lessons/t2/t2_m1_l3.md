## Цель и критерий перехода

## Теория

`std::map` хранит ключи в порядке сравнения и обычно обеспечивает `O(log n)` для поиска, вставки и удаления. `std::unordered_map` использует хеширование и в среднем обеспечивает операции близкие к `O(1)`, но худший случай может быть линейным. Порядок обхода unordered-контейнера не гарантируется.

Хеш-функция переводит ключ в число, которое помогает выбрать область хранения. Коллизии неизбежны, поэтому контейнер умеет их обрабатывать. При росте числа элементов может произойти rehash. Он перестраивает таблицу и способен инвалидировать итераторы.

Выбирай контейнер по требованиям к порядку, диапазону операций и допустимому худшему случаю. Не изменяй ключ так, чтобы изменились его хеш или порядок сравнения, пока он хранится в ассоциативном контейнере.

## Разобранный пример

```cpp
#include <unordered_map>
#include <vector>

int main() {
    const std::vector<int> data{4, 2, 4, 7, 2, 4};
    std::unordered_map<int, int> count;
    for (int value : data) ++count[value];
    return count[4] == 3 ? 0 : 1;
}
```

Частоты считаются в среднем за `O(n)`. Для отсортированного вывода используй `std::map` или отдельно отсортируй ключи.

## Практика

1. **Задача:** Посчитай частоты слов без учёта регистра для ASCII-текста.
   - **Критерий проверки:** Регистр не создаёт отдельные ключи.
   - **Подсказка:** Нормализуй токен перед вставкой.

2. **Задача:** Построй отсортированный отчёт частот и сравни `map` с `unordered_map`.
   - **Критерий проверки:** Порядок результата стабилен и объяснён.
   - **Подсказка:** Не полагайся на порядок обхода unordered-контейнера.

3. **Задача:** Спроектируй ограничение для endpoint, принимающего много пользовательских ключей.
   - **Критерий проверки:** Учтены большие входы, время и потенциально плохое хеширование.
   - **Подсказка:** Средняя сложность не отменяет лимиты ресурсов.

## Граничные случаи

- Плохой хеш; adversarial input; нестабильный порядок обхода.

## Типичные ошибки

- Ожидать стабильного порядка у `unordered_map`.
- Забывать про rehash.
- Считать среднюю сложность гарантией для любого ввода.
