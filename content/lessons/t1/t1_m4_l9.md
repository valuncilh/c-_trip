# Алгоритмы STL и ranges

- **Трек:** Основы программирования и C++
- **Модуль:** Объектная модель и стандартная библиотека
- **Тип:** урок
- **ID:** `T1-M4-L9`

## Цель и критерий перехода

Понимать требования алгоритма, сложность и границы диапазона.

## Теория

Стандартные алгоритмы отделяют способ обхода данных от операции над ними. `std::find`, `std::count_if`, `std::transform`, `std::sort` и `std::accumulate` выражают намерение и часто уменьшают число ошибок в индексах. До применения алгоритма проверь предусловия: например, `std::sort` требует диапазон с подходящими итераторами и корректный компаратор.

Ranges в C++20 позволяют передавать диапазон как единый объект и строить ленивые конвейеры через `std::views`. View обычно не владеет элементами и вычисляет преобразование по мере обхода. Время жизни исходных данных остаётся важным: диапазон, построенный поверх временного или уничтоженного объекта, может стать недействительным.

Не нужно заменять каждый цикл алгоритмом ради моды. Выбирай выражение, которое легче проверить, и учитывай сложность, аллокации и возможность раннего выхода.

## Разобранный пример

```cpp
#include <algorithm>
#include <ranges>
#include <vector>

std::vector<int> values{1, 2, 3, 4, 5, 6};
auto evenSquares = values
    | std::views::filter([](int x) { return x % 2 == 0; })
    | std::views::transform([](int x) { return x * x; });
for (int value : evenSquares) { /* 4, 16, 36 */ }
```

## Практика

1. **Задача:** Найди количество элементов, удовлетворяющих предикату, используя `count_if`.
   - **Критерий проверки:** Пустой диапазон обрабатывается корректно.
   - **Подсказка:** Предикат должен возвращать `bool`.

2. **Задача:** Построй pipeline `filter` + `transform` и материализуй результат в контейнер.
   - **Критерий проверки:** Результат не зависит от уничтоженного исходного контейнера.
   - **Подсказка:** View ленивый; при необходимости скопируй значения в `vector`.

## Граничные случаи

- Пустой диапазон; неправильный компаратор; временный диапазон и lifetime view.

## Типичные ошибки

- Использовать алгоритм с неверным компаратором.
- Считать ranges всегда владеющими данными.
- Создавать длинный pipeline, который сложнее понять, чем обычный цикл.
