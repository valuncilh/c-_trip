# CMake: targets и presets

- **Трек:** Сборка, зависимости и доставка
- **Модуль:** Сборочная система
- **Тип:** урок
- **ID:** `T4-M1-L2`

## Цель и критерий перехода

Объяснить контракт, инварианты, компромиссы и тесты; показать корректность на граничных случаях.

## Теория

CMake описывает проект и генерирует файлы для конкретной системы сборки. В современном CMake важно описывать свойства целей, а не задавать глобальные настройки для всего проекта. Цель может быть исполняемым файлом или библиотекой. Она имеет публичные заголовки, зависимости, требования к стандарту и параметры компиляции.

`target_link_libraries` описывает зависимость между целями. `target_include_directories` определяет каталоги заголовков с учётом области видимости. Публичные требования должны передаваться потребителям библиотеки, а внутренние настройки не должны случайно протекать наружу.

Build directory отделяет генерируемые файлы от исходников. Presets фиксируют повторяемые варианты конфигурации, например Debug, Release и Ninja. CTest запускает зарегистрированные тесты. Установка и export нужны, чтобы другие проекты могли использовать библиотеку без копирования её исходников внутрь проекта.

## Разобранный пример

```cmake
cmake_minimum_required(VERSION 3.25)
project(CoreDemo LANGUAGES CXX)

add_library(core src/core.cpp)
target_include_directories(core PUBLIC include)
target_compile_features(core PUBLIC cxx_std_20)

add_executable(app src/main.cpp)
target_link_libraries(app PRIVATE core)
```

`app` получает зависимость от `core`, а библиотека объявляет публичный каталог заголовков. Для полного проекта нужно добавить тестовую цель, CTest, presets и install/export.

## Практика

1. **Задача:** Создай `core` library, исполняемый файл и тестовую цель.
   - **Критерий проверки:** Каждая цель собирается независимо от текущего каталога пользователя.
   - **Подсказка:** Используй `target_link_libraries`, а не ручное копирование библиотечных файлов.

2. **Задача:** Добавь Debug и Release presets.
   - **Критерий проверки:** Новая конфигурация собирается по документированной команде.
   - **Подсказка:** Проверь генератор и каталог сборки в preset.

3. **Задача:** Добавь CTest и установку библиотеки.
   - **Критерий проверки:** Тесты обнаруживаются через `ctest`, API устанавливается отдельно от исходников.
   - **Подсказка:** Используй install rules и export set.

## Граничные случаи

- Глобальные флаги; абсолютные локальные пути; загрязнение исходников.

## Типичные ошибки

- Задавать все include-пути и флаги глобально.
- Использовать абсолютные пути к локальным файлам разработчика.
- Считать, что успешная сборка приложения доказывает корректную установку библиотеки.

## Контрольные вопросы

1. Какое условие должно выполняться до вызова решения.
2. Что произойдёт на пустом или минимальном входе.
3. Какие тесты подтверждают корректность и какие ограничения остаются.
