## Цель и критерий освоения

Ты можешь сформулировать контракт цикла, проследить его состояние после каждой итерации, исключить выход за границу и объяснить, почему алгоритм завершается.

## Перед началом

- Знать переменные, сравнения и логические условия.
- Понимать массив или std::vector на уровне доступа к элементам.

## Теория

### Ветвление выбирает путь, цикл повторяет действие

`if` выполняет одну из ветвей в зависимости от условия. `for` и `while` повторяют блок, пока условие продолжения истинно. Сам цикл не гарантирует корректность: разработчик должен определить, что происходит до первой итерации, что меняется внутри цикла и когда он завершится.

### Индексы и правая граница

У элементов последовательности из `n` значений индексы от `0` до `n - 1`. Условие `i < values.size()` корректно для прохода по всем элементам: при `i == size()` цикл останавливается до обращения к несуществующему элементу. Условие `i <= size()` обычно ошибочно при индексации, потому что разрешает лишнюю итерацию.

Пустая последовательность имеет размер 0. Цикл с начальным индексом 0 и условием `i < size()` просто не выполнится, но алгоритму всё равно может потребоваться отдельное решение для пустого входа. Например, минимум пустого набора нельзя получить через `values.front()`.

### Инвариант цикла

Инвариант — свойство, которое должно быть истинным перед первой итерацией и сохраняться после каждой итерации. Он помогает доказывать корректность циклов, а не просто проверять несколько примеров.

Для поиска минимума сформулируем инвариант: «после обработки первых `i` элементов переменная `result` содержит минимум обработанной части». В начале обрабатываем один элемент, поэтому инвариант верен. На каждой следующей итерации сравниваем новый элемент с `result` и обновляем его, только если найден меньший. После последнего элемента `result` содержит минимум всей последовательности.

### Мера прогресса и завершение

Инвариант говорит о корректности состояния, а мера прогресса — о завершении. Для цикла по индексу мера прогресса может быть числом необработанных элементов. Если на каждой итерации оно уменьшается и ограничено снизу нулём, цикл завершится.

Если счётчик не изменяется, условие может оставаться истинным бесконечно. Для цикла `while` особенно важно убедиться, что любой путь через тело делает прогресс или завершает цикл через `break`/`return`.

### Контракт алгоритма

Перед реализацией опиши допустимые входы, результат и ошибочные ситуации. Для функции минимума выберем контракт: вход содержит хотя бы один элемент; для пустого входа вызывающая сторона получает явную ошибку. Тогда алгоритм сначала проверяет пустоту и лишь после этого читает первый элемент.

Тесты должны содержать не только обычный массив: проверь пустую последовательность, один элемент, одинаковые элементы, убывающую последовательность и минимум в последней позиции. Такие тесты ловят ошибки границы и неверное обновление состояния.

## Разобранный пример

```cpp
#include <stdexcept>
#include <vector>

int minimum(const std::vector<int>& values) {
    if (values.empty()) {
        throw std::invalid_argument("empty range");
    }

    int result = values.front();

    for (std::size_t i = 1; i < values.size(); ++i) {
        if (values[i] < result) {
            result = values[i];
        }
    }
    return result;
}
```

Трассировка для `{8, 5, 6}`:

| Шаг | Значение | result до сравнения | result после |
|---|---:|---:|---:|
| Инициализация | 8 | — | 8 |
| i = 1 | 5 | 8 | 5 |
| i = 2 | 6 | 5 | 5 |

После первой итерации цикла обработана часть `{8, 5}`, и `result == 5` — её минимум. После второй обработаны все три элемента, а минимум по-прежнему равен 5. Обрати внимание: цикл начинает с индекса 1, потому что элемент с индексом 0 уже использован для начального значения.

## Практика

### Задача 1. Посчитай количество положительных значений в векторе.

**Критерий проверки.** Пустой вектор даёт 0; ноль не считается положительным; отрицательные значения не увеличивают счётчик.

> **Подсказка.** Условие — строго `value > 0`, а не `value >= 0`.

### Задача 2. Реализуй линейный поиск, который отличает индекс 0 от ответа «не найдено».

**Критерий проверки.** Первый элемент можно найти; отсутствующее значение отличается от индекса 0.

> **Подсказка.** Используй `std::optional<std::size_t>` или другой явно документированный тип результата.

### Задача 3. Для каждого своего цикла запиши инвариант и меру прогресса.

**Критерий проверки.** Инвариант описывает состояние данных, а мера прогресса объясняет завершение.

> **Подсказка.** Спроси себя: что уже обработано, что ещё предстоит обработать и как уменьшается остаток работы?

### Задача 4. Проверь функцию минимума на пустом, одиночном, убывающем и повторяющемся наборе.

**Критерий проверки.** Ошибочный вход обрабатывается явно; для остальных входов результат подтверждён ожидаемым значением.

> **Подсказка.** Особенно полезно поставить минимум в конец входного диапазона.

## Граничные случаи

- Пустой ввод.
- Ровно один элемент.
- Минимум расположен последним.
- Все элементы одинаковы.
- Индекс достигает size().
- Условие цикла истинно, но мера прогресса не уменьшается.

## Типичные ошибки

- Использовать `i <= size()` для обращения к элементам вектора.
- Обращаться к `front()` или элементу с индексом 0 до проверки пустого ввода.
- Инициализировать минимум нулём и получать неверный ответ для полностью положительного или отрицательного набора в зависимости от алгоритма.
- Описывать инвариант словами «цикл работает правильно», не указывая истинное свойство.
- Не проверять, что счётчик цикла изменяется на каждом пути исполнения.
