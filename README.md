# Вводный курс C++

Последовательное пособие по C++20 на русском языке: от инструментов и базовых конструкций до проектирования, тестирования и инженерных проектов. Главная цель — не перечислить как можно больше тем, а помочь читателю понять код, объяснить решения и закрепить знания на работающих программах.

**Текущая рабочая версия:** 1.4.0  
**Интерактивный курс:** https://valuncilh.github.io/c-_trip/

## Как устроено обучение

Курс объединяет книжный формат длинного объяснения с небольшими практическими шагами:

1. **Мотивация и модель.** Зачем нужна конструкция и какую проблему она решает.
2. **Точное объяснение.** Термины вводятся до их использования, обсуждаются ограничения и предпосылки.
3. **Разобранный пример.** Показаны код, ход выполнения и ожидаемый результат.
4. **Самостоятельная практика.** У задач есть критерии проверки и подсказки.
5. **Проверка понимания.** Рассматриваются граничные случаи, типичные ошибки и контрольные вопросы.
6. **Проект.** Несколько тем соединяются в программу, которую можно собрать и проверить.

Визуальный подход использует идеи читабельного технического пособия — ограниченную ширину строки, иерархию заголовков, оглавление главы и навигацию по разделам — вместе с практическим пошаговым ритмом интерактивных курсов. Ориентиры: [The Rust Programming Language](https://doc.rust-lang.org/book/) и [структура курса Stepik](https://help.stepik.org/article/54789).

## Что есть в репозитории

- `index.html` — автономная интерактивная версия курса с поиском, навигацией, локальным прогрессом, оглавлением урока и индикатором чтения;
- `curriculum.json` — структура курса и содержимое, встроенное в HTML;
- `content/lessons/` — исходные Markdown-версии уроков;
- `content/projects/` — проекты с исходным кодом, CMake и тестами;
- `content/images/` — иллюстрации, используемые в Markdown;
- `ROADMAP.md` — текущие направления развития;
- `VALIDATION.md` — проверяемые свойства и ограничения курса;
- `.github/workflows/` — автоматические проверки содержания, рендерера и проектов.

## Первый инженерный проект: анализатор измерений

Проект принимает числовые измерения, проверяет входные данные и вычисляет минимум, максимум, среднее значение и размах. Его структура отделяет вычислительную функцию от CLI и файлового ввода-вывода.

Подробности: [описание и инструкции](content/projects/signal-analyzer/README.md).

Проверить его локально можно так:

```sh
cd content/projects/signal-analyzer
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
./build/signal_analyzer sample_measurements.txt
```

## Проверки

GitHub Actions автоматически проверяет:
- соответствие данных внутри `index.html` файлу `curriculum.json`;
- уникальность ID, полноту навигации и наличие Markdown-источников;
- ссылки на локальные материалы и отсутствие оставшихся редакторских маркеров;
- синтаксис JavaScript и основные сценарии Markdown-рендерера;
- сборку C++20-проекта, тесты и обработку некорректного ввода.

Проверки подтверждают только описанные сценарии. Они не доказывают полноту всех тем, отсутствие всех ошибок или готовность к уровню Senior.

## Чтение и редактирование

Основной текст хранится в репозитории. Для формул LaTeX и диаграмм Mermaid браузер загружает библиотеки из сети. Прогресс и черновики редактора хранятся в текущем браузере; они не публикуются в GitHub автоматически. Для передачи черновика используется экспорт Markdown.

Для локальной иллюстрации используй Markdown-синтаксис `![Описание](./content/images/name.png)`. Поддерживаются внешние HTTPS-изображения и относительные пути от корня сайта. Alt-текст используется как подпись и как описание для вспомогательных технологий.

## Принцип качества

Урок считается полезным не потому, что в программе есть его название. Читатель должен понять предпосылки, объяснить пример своими словами, выполнить задачу, проверить границы и обосновать решение. Новые темы, проекты и визуализации добавляются по мере того, как они усиливают эту последовательность.
