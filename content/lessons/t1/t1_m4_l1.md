## Цель и критерий перехода

Отличать наследование интерфейса от повторного использования кода и безопасно проектировать полиморфизм.

## Теория

Публичное наследование уместно, когда объект производного класса действительно можно использовать вместо базового без нарушения ожиданий клиента. Если связь лишь означает «содержит» или «использует», обычно лучше композиция.

Виртуальная функция выбирается по динамическому типу объекта при вызове через ссылку или указатель на базовый класс. `override` просит компилятор проверить, что метод действительно переопределяет виртуальный метод базы. Абстрактный класс с чисто виртуальной функцией задаёт интерфейс и не создаётся напрямую.

Если объект производного класса может уничтожаться через указатель на базовый, деструктор базового класса должен быть виртуальным. Передача производного объекта по значению в параметр базового типа приводит к срезке — производная часть теряется. Для полиморфизма передавай ссылку или указатель.

## Разобранный пример

```cpp
#include <iostream>
#include <memory>
#include <vector>

struct Shape {
    virtual double area() const = 0;
    virtual ~Shape() = default;
};
struct Square final : Shape {
    explicit Square(double side) : side_(side) {}
    double area() const override { return side_ * side_; }
private:
    double side_;
};
```

## Практика

1. **Задача:** Создай базовый интерфейс `Sensor` с виртуальным `read()` и две реализации.
   - **Критерий проверки:** Код обрабатывает реализации через ссылку на базовый тип.
   - **Подсказка:** Сделай метод чисто виртуальным и добавь `override`.

2. **Задача:** Найди пример срезки объекта и исправь его.
   - **Критерий проверки:** Производная часть не теряется при передаче в обработчик.
   - **Подсказка:** Не принимай полиморфный объект по значению.

## Граничные случаи

- Удаление производного объекта через базовый указатель; срезка объекта; нарушение контракта override.

## Типичные ошибки

- Использовать наследование только ради повторного использования нескольких методов.
- Забывать виртуальный деструктор базового класса.
- Не ставить `override` и пропускать несовпадение сигнатуры.
