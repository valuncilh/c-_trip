# Строки и ввод-вывод

- **Трек:** undefined
- **Модуль:** undefined
- **Тип:** урок
- **ID:** `T1-M2-L2`

## Цель и критерий освоения

Ты можешь выбрать между operator>> и getline, безопасно обработать ошибочный ввод, проверить состояние потока и не считать частично прочитанный файл корректным целиком.

## Перед началом

- Знать переменные, ветвления, циклы и std::vector.
- Уметь открыть файл и проверить результат операции.

## Теория

### Строка — это объект, а не просто буфер символов

`std::string` — владеющая строка стандартной библиотеки. Она управляет памятью и размером текста, поэтому обычно предпочтительнее самодельного массива символов фиксированной длины. Но строка не знает смысл своего содержимого: значение `"123.4"` остаётся текстом, пока программа не преобразует его в число и не проверит, что оно допустимо.

В C++ строка типа `std::string` хранит последовательность элементов типа `char`. Это не означает, что один элемент всегда является одним пользовательским символом: UTF-8-кодовая точка может занимать несколько байтов. Для простого ASCII-формата это не проблема, но Unicode-обработка требует отдельной модели.

### operator>> и getline читают по-разному

Оператор `>>` для строки обычно читает следующий токен до пробельного символа. `std::getline(stream, line)` читает всю строку до символа конца строки, поэтому сохраняет пробелы внутри неё. Для ввода имени с пробелами или для файлов формата «одна запись на строку» чаще нужен `getline`.

После чтения числа через `>>` символ новой строки может остаться во входном потоке. Если следующим шагом вызвать `getline`, он может получить пустую строку. Это не ошибка самого getline: он прочитал то, что оставалось. При смешивании этих способов нужно осознанно очистить остаток строки, например через `std::ws` в подходящем сценарии.

### Состояние потока сообщает об успехе

Операции ввода меняют состояние потока. Цикл `while (std::getline(input, line))` обычно предпочтительнее, чем `while (!input.eof())`. EOF устанавливается при попытке чтения за концом файла; проверка eof до чтения может не заметить ошибку и привести к обработке старого значения повторно.

`failbit` означает, что операция не смогла разобрать или прочитать ожидаемые данные, а `badbit` сигнализирует о серьёзной ошибке ввода-вывода. После ошибочного числового чтения нельзя продолжать цикл без восстановления или отказа: следующая попытка может снова провалиться на том же вводе.

### Проверяй грамматику каждой записи

Для инженерного файла полезно заранее определить формат: сколько значений допустимо в строке, разделены ли они пробелами, разрешены ли комментарии, какие диапазоны принимаются. Если строка должна содержать ровно одно число, нельзя успешно прочитать первый токен и молча проигнорировать оставшийся текст.

Практичный подход для небольшого файла: читать строку, разбирать её во временном потоке, проверять наличие числа и отсутствие лишнего содержимого, затем добавлять значение в контейнер. Если одна запись повреждена, не выдавай статистику для части файла, если частичная обработка не входит в контракт.

### EOF — не единственная ошибка файла

Успешное завершение чтения в конце файла нормально. Но аппаратная или файловая ошибка может прервать чтение раньше. Проверяй `bad()` или состояние потока в соответствии с используемым интерфейсом. Закрытие файла обычно выполняется автоматически, когда объект потока выходит из области видимости; вручную управлять FILE* для обычной задачи не требуется.

## Разобранный пример

```cpp
#include <sstream>
#include <stdexcept>
#include <string>
#include <vector>

std::vector<double> parse_lines(std::istream& input) {
    std::vector<double> values;
    std::string line;
    std::size_t line_number = 0;

    while (std::getline(input, line)) {
        ++line_number;
        std::istringstream parser(line);
        double value{};
        char extra{};

        if (!(parser >> value) || (parser >> extra)) {
            throw std::runtime_error(
                "invalid line " + std::to_string(line_number));
        }
        values.push_back(value);
    }

    if (input.bad()) {
        throw std::runtime_error("I/O error");
    }
    return values;
}
```

Для упрощения пример ожидает ровно одно число в каждой строке. Пустая строка, строка с текстом и запись `1.5 V` будут отклонены. В промышленном формате нужно отдельно решить, разрешены ли комментарии, какие единицы измерения используются и как сообщать об ошибке пользователю.

Поскольку функция бросает исключение при повреждённой записи, вызывающий код не получает частичный результат как будто он полный. Для большой потоковой обработки можно выбрать другой контракт — например, вернуть отчёт об ошибках по строкам — но его следует задокументировать.

## Практика

### Задача 1. Считай строку с именем, содержащим пробел, без потери второй части.

**Критерий проверки.** Ввод `Иван Петров` сохраняется целиком.

> **Подсказка.** Используй getline вместо чтения одного токена через operator>>.

### Задача 2. Напиши разбор файла, в котором одна строка содержит одно число.

**Критерий проверки.** Строки с дополнительным текстом и пустые строки обрабатываются согласно явному контракту.

> **Подсказка.** Прочитай строку целиком, затем разбери её через std::istringstream.

### Задача 3. Отличи конец файла от невалидной строки.

**Критерий проверки.** EOF завершает цикл нормально; некорректное значение вызывает контролируемую ошибку с номером строки.

> **Подсказка.** Не используй `while (!input.eof())` как условие основного цикла чтения.

### Задача 4. Проверь файл с одной корректной и одной некорректной записью.

**Критерий проверки.** Программа не выводит итоговую статистику для частично прочитанного файла.

> **Подсказка.** Сначала считай и проверь весь файл, затем запускай расчёт.

## Граничные случаи

- Пустой файл.
- Пустая строка среди записей.
- Лишние символы после числа.
- В конце строки присутствует пробел.
- Ошибка доступа к файлу или ошибка чтения.
- Вход содержит не ASCII-текст.

## Типичные ошибки

- Считать, что operator>> и getline читают один и тот же объём текста.
- Использовать `while (!eof())` и обрабатывать последнее значение повторно.
- Игнорировать оставшийся текст после успешного чтения первого числа.
- Продолжать чтение после failbit без очистки состояния и восстановления позиции.
- Выдавать итог по первой части файла, когда последующая запись оказалась повреждена.
