# Мини-проект: анализатор измерений

**Уровень:** после основ языка, функций, контейнеров и файлового ввода-вывода  
**Стандарт:** C++20  
**Формат:** самостоятельный проект с постепенно усложняемыми требованиями

## Что построим

Консольную программу для обработки серии измерений. Каждая запись содержит номер отсчёта и измеренное значение. Программа проверяет вход, вычисляет минимум, максимум, среднее значение и размах, а затем печатает отчёт. Пример вдохновлён обычной инженерной обработкой данных, но не заменяет метрологическую оценку прибора.

## Результат первого этапа

Для данных:

```text
1.20
1.25
1.18
1.31
```

программа должна сообщить:
- количество измерений: 4;
- минимум: 1.18;
- максимум: 1.31;
- размах: 0.13;
- среднее: 1.235.

Допуск форматирования вывода — `1e-3`. В вычислениях используйте `double`, а для сравнения результата в тесте — отдельный численный допуск.

## Этап 1. Реализуй вычисления

Создай функцию:

```cpp
#include <span>

struct Statistics {
    double minimum;
    double maximum;
    double mean;
    double range;
};

Statistics calculate_statistics(std::span<const double> values);
```

Контракт:
- вход должен содержать хотя бы одно измерение;
- все значения должны быть конечными (`std::isfinite`);
- при пустом входе или NaN/бесконечности функция сообщает об ошибке через `std::invalid_argument`;
- функция не меняет входные данные.

### Рекомендуемая последовательность

1. Проверь, что диапазон не пуст.
2. Проверь каждое значение на конечность.
3. Инициализируй минимум и максимум первым элементом, не нулём.
4. Одним циклом обновляй минимум, максимум и сумму.
5. Вычисли среднее как сумму, делённую на число измерений.
6. Вычисли размах как максимум минус минимум.

Не инициализируй минимум нулём: для набора отрицательных измерений это даст неправильный ответ.

## Этап 2. Автоматические тесты

Покрой как минимум эти случаи:

| Вход | Ожидаемое поведение |
|---|---|
| `{1.2, 1.25, 1.18, 1.31}` | минимум 1.18, максимум 1.31, среднее 1.235 |
| `{-4.0, -2.0, -3.0}` | минимум -4, максимум -2, среднее -3 |
| `{5.0}` | все четыре статистики равны 5 или размаху равен 0 |
| пустой диапазон | исключение `std::invalid_argument` |
| `{1.0, NaN}` | исключение `std::invalid_argument` |
| `{1.0, +infinity}` | исключение `std::invalid_argument` |

Проверяй вещественные результаты с допуском, например:

```cpp
#include <cmath>
#include <cassert>

assert(std::abs(actual.mean - expected_mean) < 1e-9);
```

Это простой допуск для данного набора тестовых чисел, а не универсальное метрологическое правило.

## Этап 3. Разбор файла

Добавь чтение текстового файла, в котором одно измерение занимает одну строку. Программа обязана:
- отличать конец файла от ошибочного ввода;
- сообщать номер некорректной строки;
- не выдавать итоговую статистику, если хотя бы одна запись повреждена;
- не предполагать, что файл содержит хотя бы одно измерение.

Сначала загружай данные во временный контейнер и только после успешного чтения запускай расчёт. Так частично прочитанный файл не будет выглядеть как полноценный результат.

## Этап 4. Разделение ответственности

Разнеси код на:
- `statistics.hpp` — описание результата и объявление функции;
- `statistics.cpp` — алгоритм статистики;
- `main.cpp` — аргументы командной строки, ввод и отчёт;
- `tests.cpp` — проверки.

Не создавай глобальную переменную для результата. Передавай данные через параметры и возвращай вычисленную статистику.

## Этап 5. CMake

Минимальная конфигурация проекта:

```cmake
cmake_minimum_required(VERSION 3.20)
project(signal_analyzer LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)

add_library(statistics statistics.cpp)
target_include_directories(statistics PUBLIC ${CMAKE_CURRENT_SOURCE_DIR})

add_executable(signal_analyzer main.cpp)
target_link_libraries(signal_analyzer PRIVATE statistics)

enable_testing()
add_executable(statistics_tests tests.cpp)
target_link_libraries(statistics_tests PRIVATE statistics)
add_test(NAME statistics_tests COMMAND statistics_tests)
```

После сборки запусти `ctest --test-dir build --output-on-failure`.

## Критерии приёмки

- Проект собирается в режиме C++20 без расширений компилятора.
- Есть тесты для обычных, отрицательных, одиночных и некорректных данных.
- Функция вычислений не занимается чтением файлов или печатью.
- Повреждённый файл не порождает правдоподобный, но неполный отчёт.
- В README описаны сборка, запуск, формат входного файла и ограничения.
- В отчёте явно сказано: среднее — описательная статистика выборки, а не оценка точности датчика.

## Вопросы для самопроверки

1. Почему минимум и максимум нельзя начинать с нуля?
2. Почему обработку пустого диапазона надо определить контрактом?
3. Чем проверка `std::isfinite` отличается от проверки «значение не равно нулю»?
4. Почему файл нужно считать невалидным целиком, если одна из строк повреждена?
5. Почему тест сравнивает `double` через допуск, а не через `==`?
6. Какие дополнительные данные нужны, чтобы оценить неопределённость измерения?

После базовой версии добавь медиану, выборочное стандартное отклонение, пропуск комментариев в файле и экспорт CSV. Для стандартного отклонения выбери и документируй соглашение о делителе (n) или (n-1); не смешивай эти определения.
