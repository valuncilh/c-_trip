# Кэш, layout и аллокаторы

- **Трек:** Память и производительность
- **Модуль:** Низкоуровневые основы
- **Тип:** урок
- **ID:** `T6-M1-L2`

## Цель и критерий перехода

Объяснить контракт, инварианты, компромиссы и тесты; показать корректность на граничных случаях.

## Теория

Современные процессоры используют несколько уровней кэша. Последовательный доступ к памяти часто быстрее случайного, потому что процессор загружает соседние данные и эффективнее использует cache lines. Поэтому одинаковая асимптотическая сложность не означает одинаковую скорость.

AoS хранит массив структур, где все поля одного объекта лежат рядом. SoA хранит отдельно массивы разных полей. SoA может быть эффективнее, если цикл использует только часть полей всех объектов. Но реальный выбор зависит от нагрузки, не от моды.

Аллокатор влияет на цену выделения памяти и фрагментацию. Пул или arena может ускорить частые однотипные выделения, когда жизненный цикл объектов хорошо ограничен. Однако сложный аллокатор добавляет ответственность за выравнивание, освобождение, исчерпание памяти и время жизни объектов.

## Разобранный пример


```cpp
#include <vector>

struct Sample {
    float x;
    float y;
    float z;
};

void example() {
    std::vector<Sample> points;  // AoS: поля точки хранятся рядом.
    std::vector<float> x, y, z;  // SoA: поля хранятся раздельно.
}
```

Измерь обе модели на рабочем наборе данных. Сравни тот цикл, который отражает реальную задачу, и проверь результат вычислений. Сам факт использования SoA не гарантирует ускорение.


## Практика

1. **Задача:** Сравни AoS и SoA для операции, использующей только одно поле.
   - **Критерий проверки:** Есть воспроизводимый benchmark, а не вывод по ощущениям.
   - **Подсказка:** Размер данных должен превышать кэш, если исследуется работа с памятью.

2. **Задача:** Реализуй простую arena для объектов одного размера.
   - **Критерий проверки:** Проверяются выравнивание, исчерпание и отсутствие использования после сброса арены.
   - **Подсказка:** Документируй, когда объекты должны быть уничтожены.

3. **Задача:** Объясни false sharing на двух независимых счётчиках потоков.
   - **Критерий проверки:** Показано, почему независимые логические данные могут мешать из-за одной cache line.
   - **Подсказка:** Физическая близость данных влияет на coherence traffic.

## Граничные случаи

- Неверное выравнивание; исчерпание арены; ложное разделение.

## Типичные ошибки

- Считать SoA всегда быстрее AoS.
- Игнорировать разрушение объектов при сбросе arena.
- Оптимизировать layout без профилирования реальной нагрузки.
