## Цель и критерий перехода

Объяснять тип и результат выражения, не полагаясь на случайное поведение компилятора.

## Теория

При вычислении выражения важны типы операндов, правила преобразования и приоритет операторов. Например, `7 / 2` при целочисленных операндах даёт `3`, а `7.0 / 2` — `3.5`. Если результат нужен вещественный, преобразование должно произойти до деления.

`&&` и `||` используют короткое замыкание: правый операнд `&&` не вычисляется, если левый ложен; правый операнд `||` не вычисляется, если левый истинен. Побитовые `&`, `|`, `^`, `~`, `<<`, `>>` работают с битовым представлением целочисленных значений и не заменяют логические операторы.

Старайся не полагаться на неявные сужающие преобразования. `static_cast<T>(x)` явно показывает намерение, но не делает потерю данных безопасной автоматически. Переполнение знакового целого в C++ — неопределённое поведение; беззнаковая арифметика выполняется по модулю диапазона.

## Разобранный пример

```cpp
int a = 7, b = 2;
a / b;                         // 3
static_cast<double>(a) / b;    // 3.5
bool valid = (b != 0) && (a / b > 1);
unsigned mask = 1u << 3;       // бит 3
```

## Практика

1. **Задача:** Для выражений `5 / 2`, `5.0 / 2`, `-7 / 3` запиши результат и объясни правило.
   - **Критерий проверки:** Учитывается целочисленное деление с усечением к нулю.
   - **Подсказка:** Сначала определи тип каждого операнда.

2. **Задача:** Напиши проверку, которая не делит на ноль и не вычисляет опасное правое условие.
   - **Критерий проверки:** Короткое замыкание действительно защищает деление.
   - **Подсказка:** Условие `denominator != 0` должно стоять слева от `&&`.

## Граничные случаи

- Переполнение знакового целого; деление целых; сдвиг; смешение signed и unsigned.

## Типичные ошибки

- Использовать `&` вместо `&&` в условии.
- Ожидать, что `static_cast` проверит диапазон.
- Игнорировать signed/unsigned-сравнения и переполнение.
