# Идиомы C++: RAII, copy-and-swap и Rule of Five

- **Трек:** Основы программирования и C++
- **Модуль:** Объектная модель и стандартная библиотека
- **Тип:** урок
- **ID:** `T1-M4-L10`

## Цель и критерий перехода

Определять владение явно и предпочитать стандартные RAII-типы ручному управлению ресурсами.

## Теория

RAII связывает ресурс со временем жизни объекта: конструктор получает ресурс, деструктор освобождает его. Так ресурс освобождается и при обычном выходе, и при исключении. Ресурсом может быть память, файл, mutex, сокет или транзакция.

Rule of Zero: если поля сами корректно управляют ресурсами, не определяй вручную специальные функции-члены. Rule of Three напоминает, что собственный деструктор часто требует осмысленного копирующего конструктора и копирующего присваивания. В современном C++ добавляется перемещение — Rule of Five. Но это не обязанность писать все пять функций: сначала проверь, нельзя ли применить Rule of Zero.

Copy-and-swap — идиома присваивания через копию и обмен состоянием. При корректной реализации она помогает получить сильную гарантию исключений, но может быть избыточна для простых типов и требует продуманного `swap`. Не реализуй владение сырой памятью как учебный ритуал, если задачу решает `std::vector`, `std::string` или `std::unique_ptr`.

## Разобранный пример

```cpp
#include <memory>
#include <vector>

class Buffer {
public:
    explicit Buffer(std::size_t size) : data_(size) {}
    std::size_t size() const noexcept { return data_.size(); }
private:
    std::vector<std::byte> data_; // владеет памятью самостоятельно
};
// Buffer обычно не нуждается в собственных copy/move/destructor.
```

## Практика

1. **Задача:** Найди в учебном классе ручные `new[]`/`delete[]` и замени их на `std::vector`.
   - **Критерий проверки:** Утечки и двойное освобождение исключены без ручных специальных функций.
   - **Подсказка:** Сначала определи, действительно ли нужен сырой буфер.

2. **Задача:** Объясни, какие специальные функции понадобятся классу, который уникально владеет ресурсом.
   - **Критерий проверки:** Различаются копирование, перемещение и уникальное владение.
   - **Подсказка:** Подумай, должен ли ресурс копироваться или передаваться.

## Граничные случаи

- Самоприсваивание; исключение при копировании; перемещённый объект.

## Типичные ошибки

- Писать все пять специальных функций без необходимости.
- Возвращать владение сырым указателем без документированного контракта.
- Считать перемещённый объект уничтоженным — он остаётся действительным, но его значение зависит от типа.
