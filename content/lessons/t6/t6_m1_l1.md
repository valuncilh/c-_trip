# UB, alignment и object lifetime

- **Трек:** Память и производительность
- **Модуль:** Низкоуровневые основы
- **Тип:** урок
- **ID:** `T6-M1-L1`

## Цель и критерий перехода

Объяснить контракт, инварианты, компромиссы и тесты; показать корректность на граничных случаях.

## Теория

Неопределённое поведение означает, что стандарт C++ не задаёт требований к результату выполнения. Это не «обычно работает, но иногда падает». Компилятор вправе оптимизировать код, исходя из предположения, что корректная программа такого поведения не содержит. Поэтому UB может проявиться только в Release-сборке или после изменения компилятора.

У каждого объекта есть время жизни. Доступ к памяти после конца времени жизни объекта может быть ошибочным, даже если физические байты не исчезли. Alignment задаёт требования к выравниванию адреса для типа. Нарушение выравнивания может быть запрещено языком или платформой.

Не сериализуй произвольную структуру простым копированием её байтов и не считай это переносимым форматом. В объектном представлении могут быть padding bytes, endian-зависимые числа и представление, зависящее от компилятора. Для форматов задавай размеры полей и порядок байтов явно.

## Разобранный пример

```cpp
#include <cstdint>
#include <cstring>
#include <array>

std::uint32_t read_u32_le(const std::array<unsigned char, 4>& b) {
    return std::uint32_t(b[0])
        | (std::uint32_t(b[1]) << 8)
        | (std::uint32_t(b[2]) << 16)
        | (std::uint32_t(b[3]) << 24);
}
```

Преобразование явно задаёт little-endian порядок. Для реального парсера сначала проверь, что вход содержит все четыре байта, и не обращайся к данным за границами.

## Практика

1. **Задача:** Найди UB в наборе примеров и объясни, почему наблюдаемый результат не является гарантией.
   - **Критерий проверки:** Каждый дефект классифицирован, исправлен и покрыт тестом.
   - **Подсказка:** Проверь signed overflow, lifetime, границы и aliasing.

2. **Задача:** Реализуй чтение целого из бинарного формата с проверкой длины.
   - **Критерий проверки:** Усечённый вход возвращает ошибку, а не читает память за пределами.
   - **Подсказка:** Сначала проверь доступный размер, затем декодируй.

3. **Задача:** Собери один пример в Debug и Release и сравни поведение.
   - **Критерий проверки:** Разница используется как повод исследовать UB, а не как доказательство правильности одной конфигурации.
   - **Подсказка:** Добавь UBSan и уменьшай пример.

## Граничные случаи

- Невыровненный доступ; чтение неинициализированной памяти; strict aliasing.

## Типичные ошибки

- Считать физически доступные байты гарантией живого объекта.
- Копировать структуру в файл и называть это переносимым форматом.
- Опираться на конкретное проявление UB.
