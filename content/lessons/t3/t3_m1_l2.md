# RAII и умные указатели

- **Трек:** Современный C++ и ресурсы
- **Модуль:** Время жизни и объектная модель
- **Тип:** урок
- **ID:** `T3-M1-L2`

## Цель и критерий перехода

Объяснить контракт, инварианты, компромиссы и тесты; показать корректность на граничных случаях.

## Теория

RAII связывает ресурс с временем жизни объекта. Когда объект уничтожается, его деструктор освобождает ресурс. Это работает при обычном возврате и при раскрутке стека из-за исключения. Так управляют памятью, файлами, mutex, сокетами и транзакциями.

`unique_ptr` выражает единоличное владение. Его перемещают, но не копируют. `shared_ptr` хранит совместное владение и уничтожает объект после исчезновения последнего владельца. Совместное владение усложняет модель и не должно быть выбором по умолчанию. Цикл `shared_ptr` может удерживать объекты бесконечно. `weak_ptr` даёт наблюдение без владения.

Rule of Zero советует строить классы из уже безопасных типов, чтобы не писать вручную деструктор и операции копирования/перемещения без необходимости.

## Разобранный пример

```cpp
#include <fstream>
#include <stdexcept>

void write_value(const char* path, int value) {
    std::ofstream file(path);
    if (!file) throw std::runtime_error("cannot open output");
    file << value << '\n';
    if (!file) throw std::runtime_error("write failed");
}
```

Поток сам управляет файловым ресурсом. Отдельная проверка после записи нужна, потому что успешное открытие не гарантирует успешное завершение записи.

## Практика

1. **Задача:** Замени `new` и `delete` на `std::unique_ptr`.
   - **Критерий проверки:** Нет двойного удаления и ручного освобождения.
   - **Подсказка:** Рассмотри `std::make_unique`.

2. **Задача:** Разорви цикл совместного владения через `weak_ptr`.
   - **Критерий проверки:** Объекты освобождаются после исчезновения внешних владельцев.
   - **Подсказка:** Обратная связь часто должна быть невладеющей.

3. **Задача:** Сделай RAII-обёртку файлового дескриптора.
   - **Критерий проверки:** Дескриптор закрывается на всех путях, включая ошибку.
   - **Подсказка:** Запрети копирование владельца или явно опиши передачу владения.

## Граничные случаи

- Исключение в конструкторе; двойное владение сырого указателя; цикл владения.

## Типичные ошибки

- Использовать `shared_ptr` для всех объектов.
- Создавать независимые `shared_ptr` из одного сырого адреса.
- Игнорировать ошибки записи после открытия файла.
