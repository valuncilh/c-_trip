## Теория

### Контейнер решает задачу хранения

Контейнер — объект стандартной библиотеки, который управляет группой значений. `std::vector<T>` хранит элементы в непрерывной области памяти и автоматически управляет её размером. Он подходит для последовательности, где часто читают элементы по индексу, перебирают их и добавляют значения в конец.

Вектор владеет своими элементами. Это значит, что при уничтожении вектора его элементы тоже уничтожаются. Не нужно вручную выделять и освобождать память, как при работе с сырыми массивами, если стандартный контейнер уже решает задачу.

### size и capacity — разные понятия

`size()` — количество реально существующих элементов. Допустимые индексы: от 0 до `size() - 1`, если вектор не пуст. `capacity()` — количество элементов, для которых уже выделена память без обязательного перераспределения. Вектор может иметь запас ёмкости, но элементы за пределами `size()` не существуют и читать их нельзя.

`reserve(n)` просит выделить ёмкость как минимум для `n` элементов, но не добавляет элементы и не меняет размер. `resize(n)` меняет количество элементов и при увеличении создаёт новые элементы. Эти операции нельзя подменять друг другом.

### Перебор элементов

Для чтения часто удобен range-based for:

```cpp
for (const int value : values) {
    // value — копия очередного элемента
}
```

Если нужен индекс, используй условие `i < values.size()`. Если элемент большой и копировать его не нужно, может пригодиться `const auto& value`. Ссылка позволяет читать сам элемент, а не копию. Не возвращай ссылку за пределы времени жизни контейнера.

### Итераторы и границы диапазона

Итератор — объект, который обозначает позицию в последовательности и позволяет перейти к элементам по правилам контейнера. У стандартных контейнеров диапазон обычно задаётся полуинтервалом `[begin(), end())`: начало включено, конечная позиция не обозначает существующий элемент и служит границей обхода.

Алгоритмы STL часто принимают пару итераторов, поэтому понимание полуинтервала важно. Если `begin() == end()`, диапазон пуст и его безопасно обходить стандартным алгоритмом, который поддерживает пустые диапазоны.

### Инвалидация ссылок и итераторов

Когда `push_back` увеличивает размер за пределы текущей ёмкости, вектор может выделить новый блок памяти и переместить элементы. Старые указатели, ссылки и итераторы на элементы при перераспределении становятся недействительными. Даже когда перераспределения нет, вставка или удаление в середине может переместить элементы и нарушить прежние позиции.

Не сохраняй итератор, а затем не изменяй контейнер, предполагая, что итератор всё ещё валиден. Сначала заверши изменения, затем получи нужные итераторы заново. `reserve` иногда помогает избежать перераспределения при известном количестве добавлений, но не отменяет все правила инвалидации.

## Разобранный пример

```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<int> samples{12, 15, 11};

    samples.push_back(18);
    samples.reserve(16);

    std::cout << "size = " << samples.size() << '\n';
    std::cout << "capacity = " << samples.capacity() << '\n';

    for (std::size_t i = 0; i < samples.size(); ++i) {
        std::cout << i << ": " << samples[i] << '\n';
    }
}
```

После `push_back` размер равен 4, а `reserve(16)` просит ёмкость не меньше 16. Фактическая ёмкость может быть больше 16 — стандарт не требует, чтобы она была ровно равна аргументу. Обращаться к `samples[4]` после этого всё ещё нельзя: ёмкость — это не число существующих элементов.

## Практика

### Задача 1. Реализуй функцию, которая возвращает сумму элементов вектора.

**Критерий проверки.** Пустой вектор даёт сумму 0; исходный вектор не изменяется.

> **Подсказка.** Для суммирования не обязательно использовать индексы — попробуй range-based for.

### Задача 2. Найди максимум последовательности и определи контракт пустого диапазона.

**Критерий проверки.** Отрицательные значения обрабатываются правильно; поведение при пустом входе явно определено.

> **Подсказка.** Не инициализируй максимум нулём, если допустимы отрицательные измерения.

### Задача 3. Создай вектор с известным количеством элементов, используй `reserve` и сравни size и capacity.

**Критерий проверки.** Ты можешь объяснить, почему резервирование не создаёт элементы.

> **Подсказка.** Печатай обе величины до и после reserve.

### Задача 4. Напиши код, который добавляет элементы и не использует сохранённые ссылки после потенциального перераспределения.

**Критерий проверки.** После модификации контейнера ссылка/итератор заново получен или не используется.

> **Подсказка.** Проверь, где именно могут выполниться `push_back` или `insert`.

## Граничные случаи

- Пустой вектор.
- Один элемент.
- Только отрицательные значения.
- Рост размера приводит к перераспределению.
- Удаление или вставка в середине меняет позиции элементов.

## Типичные ошибки

- Считать, что capacity — количество доступных для чтения элементов.
- Обращаться к индексу, равному size().
- Хранить итератор или ссылку через вызов, который может перераспределить память.
- Использовать `reserve` вместо `resize`, ожидая создания элементов.
- Копировать большой элемент в цикле, когда требуется только чтение.
