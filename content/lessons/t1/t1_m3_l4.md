## Цель и критерий освоения

Ты умеешь читать объявления указателей с const, безопасно проверять время жизни адресуемого объекта и объяснять границы допустимой арифметики указателей.

## Перед началом

## Теория

### Адрес и значение — разные вещи

Переменная хранит значение, а указатель может хранить адрес объекта. Оператор `&value` получает адрес существующего объекта, а оператор `*ptr` обращается к объекту по этому адресу. Эти операции выполняют противоположные действия: взять адрес и разыменовать указатель.

`nullptr` обозначает указатель, который ни на какой объект не указывает. Он полезен для выражения необязательного результата, но разыменовывать его нельзя. Проверка `if (ptr != nullptr)` защищает только от нулевого указателя; она не доказывает, что любой ненулевой адрес всё ещё указывает на живой объект.

### Время жизни важнее числа в адресе

Указатель не владеет объектом автоматически и не продлевает его время жизни. Если локальная переменная уничтожена, сохранённый адрес больше нельзя разыменовывать. Такой указатель называют висячим. То же относится к указателю на элемент вектора после операции, которая перераспределила память, или к адресу после освобождения динамического ресурса.

В современном C++ выражай владение стандартными объектами и RAII-контейнерами, а не сырыми указателями. Ссылка подходит для обязательного аргумента, указатель — когда отсутствие объекта является частью контракта, а `std::unique_ptr<T>` — когда нужно выразить эксклюзивное владение динамическим объектом.

### Арифметика указателей ограничена массивом

Указатель можно перемещать внутри одного массива. Также разрешено получить указатель на позицию сразу за последним элементом: он используется как конечная граница диапазона. Но эту позицию нельзя разыменовывать. Нельзя переносить указатель в произвольную память и считать, что такая арифметика автоматически корректна.

Вычитать два указателя можно, когда они обозначают элементы одного массива или позицию сразу за ним; результат выражает расстояние в элементах, а не в байтах. Для обычного обхода контейнера предпочитай индексы, диапазонный цикл или итераторы, если они делают границы понятнее.

### Как читать const у указателя

Положение `const` определяет, что именно запрещено менять:

- `const int* p` — через `p` нельзя менять значение объекта, но `p` можно переназначить;
- `int* const p` — сам `p` нельзя переназначить, но объект можно менять через `*p`;
- `const int* const p` — нельзя ни менять объект через `p`, ни переназначать `p`.

Это ограничение действует через конкретное выражение доступа. `const` не делает объект глобально неизменяемым, если к нему существует другой изменяемый путь.

### Указатель, ссылка и владение

Ссылка должна быть привязана к объекту при инициализации и в обычном использовании не переназначается. Указатель может быть нулевым и менять адрес. Поэтому указатель подходит для необязательной ссылки на объект, а обычная ссылка лучше передаёт требование «объект обязательно существует».

Сырой указатель чаще всего следует воспринимать как невладеющий доступ, если контракт не говорит обратного. Не смешивай «адрес объекта» с «ответственностью за уничтожение объекта»: эта ответственность должна быть выражена отдельно.

## Разобранный пример

```cpp
#include <iostream>

int main() {
    int values[] = {10, 20, 30};

    int* p = values;
    std::cout << *p << '\n';
    std::cout << *(p + 2) << '\n';

    const int* read_only = values;
    int* const fixed_address = values;

    // *read_only = 7;    // ошибка: нельзя менять через const int*
    *fixed_address = 7;   // допустимо: объект изменяемый
    // fixed_address = nullptr; // ошибка: сам указатель const
    std::cout << values[0] << '\n';
}
```

Указатель `p` первоначально указывает на `values[0]`. Выражение `p + 2` указывает на третий элемент того же массива. Оно допустимо, потому что остаётся внутри массива. Но `p + 3` — только конечная позиция; разыменовывать её нельзя.

`read_only` запрещает изменение значения через него. `fixed_address` нельзя переназначить, но он допускает изменение элемента, потому что тип объекта — не const.

## Практика

### Задача 1. Напиши функцию поиска максимума, принимающую `const std::vector<int>&`.

**Критерий проверки.** Функция не копирует вектор и не меняет его; поведение на пустом векторе определено контрактом.

> **Подсказка.** Для обязательного объекта используй ссылку, а const запрещает менять элементы через параметр.

### Задача 2. Найди висячий указатель в учебном примере и исправь его.

**Критерий проверки.** Объяснено, где заканчивается время жизни адресуемого объекта, и после этого обращения нет.

> **Подсказка.** Проверь возвращаемый адрес локальной переменной и элементы после изменения контейнера.

### Задача 3. Предскажи, какие из объявлений `const int*`, `int* const` и `const int* const` позволяют переназначить указатель.

**Критерий проверки.** Отдельно определено, можно ли менять объект и можно ли менять адрес.

> **Подсказка.** Читай от имени переменной: const относится к объекту слева, если слева есть тип, иначе к указателю.

### Задача 4. Объясни, почему указатель за концом массива допустим для сравнения, но не для разыменования.

**Критерий проверки.** В ответе различаются конечная граница диапазона и существующий элемент.

> **Подсказка.** Вспомни полуинтервал [begin, end).

## Граничные случаи

- nullptr.
- Висячий указатель после завершения жизни объекта.
- Перераспределение vector.
- Адрес на one-past-the-end позицию.
- Перепутанное расположение const.
- Невладеющий указатель дольше владельца.

## Типичные ошибки

- Разыменовывать `nullptr`.
- Возвращать адрес локальной переменной или сохранять его после завершения её времени жизни.
- Считать, что ненулевой указатель всегда валиден.
- Разыменовывать указатель на позицию за концом массива.
- Считать `const int*` и `int* const` эквивалентными объявлениями.
- Использовать сырой указатель для владения ресурсом, не определив правила освобождения.
