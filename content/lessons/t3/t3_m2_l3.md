## Теория

Итераторы позволяют алгоритмам работать с различными контейнерами, но их возможности различаются. Итератор вектора поддерживает арифметику и произвольный доступ. Итератор списка подходит для последовательного обхода, но не для быстрого перехода к произвольному индексу.

Стандартные алгоритмы выражают намерение яснее ручного цикла, если соблюдены их требования. `std::sort` требует подходящей категории итератора. `std::find` работает с последовательным обходом. Изменение контейнера может инвалидировать итераторы, поэтому правила конкретной операции важны.

Ranges и views строят ленивые конвейеры. View может ссылаться на источник, не владея им. Источник должен жить дольше обхода. Создание view не обязательно вычисляет все значения. Вычисление может произойти только при итерации.

## Разобранный пример

```cpp
#include <ranges>
#include <vector>

int main() {
    std::vector<int> values{1, 2, 3, 4, 5, 6};
    auto even_squares = values
        | std::views::filter([](int x) { return x % 2 == 0; })
        | std::views::transform([](int x) { return x * x; });

    for (int value : even_squares) (void)value;
}
```

Отдельный результирующий вектор не создаётся. Если `values` уничтожить или изменить так, что итераторы инвалидируются, view станет небезопасен.

3. **Задача:** Создай view, а затем измени источник до обхода.
   - **Критерий проверки:** Ты можешь объяснить, когда источник остаётся валидным.
   - **Подсказка:** View, как правило, не владеет диапазоном.

## Граничные случаи

- View ссылается на уничтоженный источник; изменение контейнера во время обхода.

## Типичные ошибки

- Использовать алгоритм с неподходящей категорией итератора.
- Продолжать обход инвалидированным итератором.
- Считать view материализованной коллекцией.
